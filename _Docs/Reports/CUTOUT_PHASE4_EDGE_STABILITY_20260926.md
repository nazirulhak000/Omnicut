## 1. สรุปผล — โหมด default แทบไม่ช่วยอะไร

วัดฟุตเทจจริง BLU01 (`bluwow cx07.mov`) สองช่วง ช่วงละ 60 เฟรม ที่ 960x540
เทียบสามโหมดบน**เฟรมชุดเดียวกัน** (เครื่องมือรัน rembg เองทั้งสามโหมด)

| window | mode | boundary MAE | เทียบ raw |
| :--- | :--- | ---: | ---: |
| 22.0–24.0s | `off` (raw rembg) | 0.0657 | baseline |
| | **`legacy`** (ค่า default) | 0.0661 | **−0.7%** |
| | **`motion`** (opt-in) | 0.0522 | **+20.5%** |
| 45.0–47.0s | `off` (raw rembg) | 0.1000 | baseline |
| | **`legacy`** (ค่า default) | 0.1003 | **−0.3%** |
| | **`motion`** (opt-in) | 0.0874 | **+12.7%** |

**ทิศทางตรงกันทั้งสองช่วง:**
- `legacy` = โหมดที่ผู้ใช้ได้จริงโดยไม่ต้องตั้งอะไร → **ไม่ได้ลดขอบสั่น** (แย่กว่าไม่ทำเล็กน้อย 0.3–0.7%)
- `motion` = โหมดที่ต้องกดเปิดเอง → **ลดขอบสั่นได้จริง 12.7–20.5%**

`motion_compensated_boundary_mae` คือความต่างของ mask ที่ขอบ **หลังชดเชยการเคลื่อนไหวด้วย optical flow แล้ว**
ค่านี้ต่ำ = ขอบนิ่ง ไม่กระพริบระหว่างเฟรม ซึ่งคือสิ่งที่ Phase 4 ต้องการวัดพอดี

## 2. ทำไม legacy ถึงไม่ช่วย — คำตอบอยู่ในคอมเมนต์ของโค้ดเอง

`scripts/background_isolation_video_worker.py:214-220`

```python
elif previous_alpha is not None and temporal_mode == "legacy":
    # Smooth small per-pixel fluctuations only; moving edges
    # with larger differences retain their current mask.
    difference = ImageChops.difference(previous_alpha, alpha)
    stable = difference.point(lambda value: 255 if value < 24 else 0)
    smoothed = Image.blend(previous_alpha, alpha, 0.65)
    alpha.paste(smoothed, mask=stable)
```

legacy เกลี่ยเฉพาะพิกเซลที่ต่างจากเฟรมก่อน **น้อยกว่า 24** เท่านั้น
แต่ขอบที่เคลื่อนไหว — ซึ่งเป็นต้นตอของอาการสั่น — ต่างกันมากกว่านั้นเสมอ จึง**ถูกข้ามไปทั้งหมด**

ไม่ใช่บั๊ก โค้ดทำตามที่คอมเมนต์เขียนไว้เป๊ะ แต่แปลว่า**เอฟเฟกต์ที่ตั้งใจให้แก้อาการสั่น ไปไม่ถึงจุดที่สั่น**

ส่วน `motion` (`scripts/cutout_temporal.py`) ใช้ optical flow warp mask เฟรมก่อนมาเทียบ
จึงตามขอบที่เคลื่อนไหวได้ และมี scene-cut reset กัน mask เก่าลากข้ามช็อต

## 4. ข้อเสนอ — ยังไม่เปลี่ยน default

**ข้อมูลชี้ว่าควรเปลี่ยน default จาก `legacy` เป็น `motion`** เพราะ:
- `legacy` ไม่ให้ประโยชน์ที่วัดได้ แต่ยังกิน compute (blend ทุกเฟรม)
- `motion` ให้ผลจริง 12.7–20.5% และมีเทสคุมอยู่แล้ว (`tests/test_cutout_temporal.py`)

**แต่ยังไม่เปลี่ยนในรอบนี้** เพราะ:
1. ยังไม่ได้วัดว่า `motion` เพิ่มเวลา encode เท่าไร (Phase 0 วัดไว้บน `legacy`)
2. วัดมาสองช่วงจากคลิปเดียว — ยังไม่ครอบคลุมช็อตนิ่ง ช็อตหลายวัตถุ หรือคลิปอื่น
3. `IoU vs raw rembg` ของ motion ต่ำกว่าเล็กน้อย (0.9964 / 0.9973) แปลว่า mask ขยับจาก raw จริง
   ซึ่ง**เป็นผลที่ตั้งใจ** แต่ควรให้คนดูภาพยืนยันว่าไม่กินขอบวัตถุ ก่อนบังคับใช้กับทุกคน

เป็นการตัดสินใจของเจ้าของโปรเจกต์ ไม่ใช่สิ่งที่ควรเปลี่ยนเงียบๆ จากตัวเลขสองช่วง

## 5. ข้อจำกัดของการวัดนี้

- **ไม่มี ground truth** เครื่องมือระบุเองว่า `Spatial IoU compares to raw rembg, NOT annotated ground truth`
  จึง**ไม่สรุปว่าโหมดไหนเลือกวัตถุถูกกว่า** วัดได้แค่ว่าขอบนิ่งกว่ากันแค่ไหน
- วัดที่ 960x540 ไม่ใช่ 1920x1080 เต็ม (ต้นทุน ~1/4) ตัวเลขสัมบูรณ์จะต่างที่ความละเอียดจริง
  แต่การเทียบระหว่างโหมดยังใช้ได้เพราะทุกโหมดวัดบนเฟรมชุดเดียวกัน
- `valid_boundary_coverage` ของ window ที่สองคือ 0.7603 (ต่ำกว่า 0.9693 ของช่วงแรก)
  แปลว่า optical flow เชื่อถือได้น้อยกว่าในช่วงนั้น จึงให้น้ำหนักผลช่วงแรกมากกว่า
- ยังไม่ได้วัดครบทั้ง 4 source windows ของ BLU01
