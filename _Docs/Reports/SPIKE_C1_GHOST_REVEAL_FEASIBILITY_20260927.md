## C1 — `\fscx114\fscy114` ทำสระ/วรรณยุกต์ไทยพังไหม?

**ผล: ไม่พัง** — ข้อกังวลที่ comment `scripts/subtitle_engine.py:842` เตือนไว้ ไม่ตรงกับพฤติกรรม libass ปัจจุบัน

**วิธีวัด:** เรนเดอร์ ffmpeg จริงผ่าน libass ด้วยสเปก SOP (fs=88, outline=5.2, MarginV=380) คำทดสอบเลือกจากกรณีบีบคั้นที่สุด — สระบน+วรรณยุกต์ซ้อนชั้น (`ที่`, `เชื่อม`), สระล่าง (`ปุ่ม`), สระอำ+ไม้โท (`น้ำ`), ทัณฑฆาต (`สมาร์ท`) แล้วเทียบ 2 แบบ: ไม่ใส่ tag vs ใส่ `\fscx114\fscy114`

**หลักฐานเชิงตัวเลข** (นับ band แนวนอนของหมึก — มาร์คหลุด/ยุบจะทำจำนวน band เปลี่ยน):

| ฟอนต์ | band plain vs scaled | h ratio | w ratio |
|---|---|---|---|
| Kanit | เท่ากันทุกคำ (2,1,2,1,2) | 1.130–1.146 | 1.142–1.200 |
| Mali | เท่ากันทุกคำ (2,2,1,1,1) | 1.116–1.163 | 1.133–1.140 |

ratio เกาะ 1.14 ตามที่ tag กำหนด และตรวจภาพขยาย 3x ด้วยตา — สระ วรรณยุกต์ ทัณฑฆาต อยู่ตำแหน่งเดิมทุกคำ ไม่ลอย ไม่ฉีก ไม่ทับ

**ffmpeg ที่ใช้:** `2025-12-10-git-4f947880bd` (มี libass) — ข้อควรระวัง: ถ้าย้ายเครื่องหรือ downgrade ffmpeg ต้องรันซ้ำ เพราะผลนี้ผูกกับเวอร์ชัน libass

## C3 — edge-TTS WordBoundary แม่นพอไหม?

**ผล: แม่นพอ** — ใช้เป็นแหล่งจังหวะของ reveal ได้

ทดสอบบทไทยจริง 1 ประโยค (`th-TH-NiwatNeural`, rate `+15%` ตาม config):

| ตัวชี้วัด | ค่า | ประเมิน |
|---|---|---|
| จำนวนคำ | 14 | ตัดตามคำไทยถูกต้อง — `สมาร์ทโฟน` เป็นก้อนเดียว ไม่ฉีก |
| ประกอบข้อความกลับ | ตรงต้นฉบับ 100% | ไม่มีคำหาย/เพี้ยน (ต่างจาก Whisper) |
| ช่วงเวลาคาบเกี่ยว | 0 จุด | ไม่ต้องแก้ overlap |
| ช่องว่างระหว่างคำ | 0.000–0.130s | ไม่มีรูโหว่ผิดปกติ |
| ครอบคลุม | คำสุดท้ายจบ 3.072s / เสียง 3.840s | หาง 0.768s เป็นความเงียบหลังพูดจบ ปกติ |

**ข้อจำกัดที่ต้องจัดการในรอบ B:** `scripts/stages/voice_stage.py` default เป็น `gemini_tts` ซึ่งใช้ RMS alignment **ไม่มี word_timings เลย** → เปิดสไตล์นี้ต้องบังคับใช้ edge-TTS path หรือหาแหล่ง timing สำรอง

## C4 — Mali-Bold ใช้ได้ไหม?

**ผล: ใช้ได้** — `02_Assets/Fonts/Mali-Bold.ttf` มีอยู่แล้ว เรนเดอร์ผ่าน libass ได้ปกติที่ 88px

- รูปทรงกลม เป็นมิตร แยกจาก Kanit ชัดเจน เข้าโทนรีวิวแกดเจ็ตตาม SOP
- ทนการขยาย 114% เท่า Kanit (ดูตาราง C1)
- **ข้อสังเกต:** ก้านตัวอักษรบางกว่า Kanit ที่ขนาดเดียวกัน — outline 5.2 ตาม SOP ช่วยชดเชยได้ ควรตรวจซ้ำบนฉากหลังสว่าง
- ยังไม่อยู่ใน `FONT_OPTIONS` (`frontend/src/components/editor/inspector/CaptionInspector.jsx:50-55`) → รอบ B ต้องเพิ่ม + ลงทะเบียนทั้งฝั่ง Python resolver และ JS canvas

## C5 — ข้อสรุปและผลต่อแผนรอบ B

**เปลี่ยนแปลงจากแผนเดิม:**
1. **ตัด C2 ออก** — ไม่ต้องหา active-state ทดแทน ใช้ `\fscx114\fscy114` ตาม SOP ตรงตัว
2. **B2 ง่ายลง** — ghost reveal ใช้เทคนิค 3 สถานะได้ครบตาม SOP (ghost `\alpha&HFF&` / active `#66FF00`+`\fscx114` / spoken `#FFFFFF`)
3. **เพิ่มงานใน B1** — ต้องจัดการกรณี `gemini_tts` ไม่มี word_timings: บังคับ edge-TTS เมื่อเปิดสไตล์ หรือ fallback แบ่งตามสัดส่วนตัวอักษร (ต้องถามผู้ใช้ว่าเอาแบบไหน)
4. **B8 ต้องเพิ่ม assertion** ผูกเวอร์ชัน libass — ผล C1 ผูกกับ ffmpeg build ปัจจุบัน

**ความเสี่ยงที่เหลือ (ยังไม่พิสูจน์):**
- ยังไม่ได้ทดสอบ `\fscx114` ตอนมีหลายคำในบรรทัดเดียว + ghost placeholder — คำอาจขยับแนวนอนตอนคำ active โต ต้องพิสูจน์ในรอบ B
- ยังไม่ได้วัด drift สะสมเมื่อเสียงยาว 60 วินาที (ทดสอบแค่ 3.8s)
- preview canvas ยังไม่ได้เทียบกับ ASS ที่ 114%
