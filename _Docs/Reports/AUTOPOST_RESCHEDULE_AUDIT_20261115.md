## ข้อสรุป

## 1. P1 — เวลาในคิวปกติกับ posting job ต่างกันได้

**ยืนยันด้วย offline endpoint probe**

ตำแหน่ง: `scripts/api_tiktok_autopost.py:378–386`, `:490`, `:517–539`, `:831–853`

การเช็ก `posting_slot_mismatch` อยู่ภายในแขนง `publish_draft` เท่านั้น งาน `schedule` ปกติที่มี queue_id ใช้เวลาจาก request สร้าง job โดยไม่ตรวจว่าเท่ากับเวลาในคิว และการผูก job/บันทึกผลกลับไม่ซิงก์ scheduled_at จาก job

จำลอง: คิว planned จองวันที่ +2 เวลา 09:00 แต่ส่ง prepare ด้วยวันที่ +3 เวลา 16:00 → HTTP 200 และคิวยังเก็บวันที่ +2 เวลา 09:00 ขณะที่ job ได้เวลาที่ส่งใหม่

ผลกระทบ: UI และการจองช่องเวลาบอกคนละเวลาจากงานที่จะส่ง TikTok; การตรวจคลิปถึงเวลาและการจัดคิวต่อไปอ้างเวลาที่ผิดได้ ยังไม่ได้จำลองการกด TikTok จริง

แก้ขั้นต่ำ: ทุก intent ที่มีเวลาต้องตรวจ queue revision และเวลาเดียวกับคิว ถ้าผู้ใช้แก้ในฟอร์ม ให้บันทึกและตรวจความขัดแย้งที่คิวก่อนเตรียม ห้ามให้ prepare เปลี่ยนเวลาลับหลังตาราง

เกณฑ์รับงาน: request ที่อ้างคิวเก่าได้ 409 ก่อนสร้าง job; คิว/job/UI หลังเตรียมและหลัง receipt แสดง Bangkok slot เดียวกัน

## 8. P3 — ข้อความและข้อมูลตัวอย่างยังช่วยตัดสินใจไม่พอ

- “จัดเวลาใหม่สำเร็จ” เป็นการเปลี่ยนคิวในโปรแกรม ไม่ใช่ TikTok รับตั้งเวลาแล้ว ต้องระบุให้เห็นใกล้ปุ่ม และบอกขั้นตอน “เลือกคลิป → เริ่มรัน”
- ควรอธิบายสาเหตุที่ข้ามช่องว่าง: สินค้าเดียวกัน/สี Hook ซ้ำต่อวัน/ช่องถูกจอง/เกินช่วงที่เลือก แทนเหตุผลรวมข้อความเดียว
- ควรแสดงครบ: จำนวนย้าย, จำนวนไม่ย้าย, ช่วงวันที่ใหม่, แบบร่างกี่คลิป, รอโพสต์กี่คลิป และรายละเอียดครบทุกตัว
- ควรเลือก scope ได้: ทั้งช่อง/เฉพาะที่เลือก/ช่วงวันที่ โดยค่าเริ่มต้นระบุชัด ไม่เปลี่ยนเงื่อนไขแบบเงียบ
- พิจารณาระยะเผื่ออัปโหลดเพิ่มจากขั้นต่ำ 15 นาทีตามจำนวนคลิป เพราะตรวจผ่านตอนวางแผนไม่ได้รับรองว่าคลิปท้าย batch จะเหลือเวลาเพียงพอเมื่ออัปโหลดถึงตัวนั้น; worker มี guard ช่วยหยุด แต่ควรเตือนล่วงหน้า

## ส่วนที่ตรวจแล้วมีตัวกันอยู่

- reschedule bulk เปลี่ยนเฉพาะ planned/draft_on_platform ไม่ดึง scheduled_on_platform/posted มาย้าย
- preview ไม่เขียนคิว; commit มี transaction แบบ all-or-nothing ตรวจรายการซ้ำ ช่องเวลาซ้ำ ช่วงเวลา และกฎรายวันซ้ำอีกครั้ง
- parser แปลง timezone ไป Bangkok และบังคับรอบ 5 นาที; sidebar ใช้ Intl Asia/Bangkok แสดงเวลา
- แบบร่างรักษา job และสถานะเดิมเมื่อย้ายเวลา ไม่อัปโหลดซ้ำด้วยการ reschedule เพียงอย่างเดียว
- Escape/Cancel ใน dialog ให้ผล false และล้าง listener; มีการป้องกันรัน batch ซ้อนในเส้นหลัก
- ไม่มีหลักฐานใหม่ในรอบนี้ว่ากลไกเหล่านี้เสีย; ไม่เท่ากับรับรอง selector/ผลลัพธ์บน TikTok จริง
