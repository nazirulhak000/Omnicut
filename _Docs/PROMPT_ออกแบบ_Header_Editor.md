## ปัญหาที่วัดได้ (ห้ามเชื่อลอยๆ ให้วัดซ้ำเองก่อนออกแบบ)

จอ 1920 กว้าง:
- คอนโทรล 9 ตัวเรียงแถวเดียวรวด รวมกว้าง ~869px ไม่มีการจัดกลุ่มเลย
- สูง 55px

จอ 500 กว้าง (ผู้ใช้ใช้จริงแบบนี้ หน้าต่างแคบข้างจอ):
- คอนโทรล 6 ตัวกิน 418px จาก 498px = **84% ของความกว้าง** เหลือช่องว่าง 80px หาร 5 ช่อง
- ช่องเลือกโปรเจกต์ยุบเหลือ **37px** — โชว์แค่ "—" อ่านไม่ออกว่ากำลังแก้คลิปไหน
- ช่องเลือกคุณภาพส่งออกกิน **190px = 38% ของ header** ทั้งที่นานๆ เปลี่ยนที
- ปุ่มเรนเดอร์ถูกไอคอนอื่นทับ

**แก่นของปัญหา: ของสำคัญสุดเล็กสุด ของใช้น้อยสุดใหญ่สุด และทุกอย่างอยู่ระนาบเดียวกันหมด**

## ของที่อยู่ใน header ตอนนี้ (ห้ามตัดฟีเจอร์ทิ้ง ย้ายที่ได้)

| ของ | ใช้บ่อยแค่ไหน | หมายเหตุ |

| ป้าย "ตัดต่อมือ" + ไอคอน | ไม่เคยกด | เป็นแค่ label |
| เลือกโปรเจกต์ (dropdown) | บ่อย | บอกว่ากำลังแก้อะไรอยู่ — สำคัญสุด |
| โหลดใหม่ | นานๆ ครั้ง | |
| ลบโปรเจกต์ | นานๆ ครั้ง | destructive ต้องแยกจากปุ่มปกติ |
| คลิปใหม่ | บ่อย | กลับไปหน้าสร้าง |
| ขยายพรีวิว (zen) | ปานกลาง | โผล่เฉพาะตอนเปิดโปรเจกต์ |

| คุณภาพส่งออก (โพสต์จริง/ทดลอง) | ปานกลาง | ผูกกับปุ่มเรนเดอร์ |
| ปุ่มเรนเดอร์ | บ่อยที่สุด | primary action หนึ่งเดียวของหน้า |
| timecode (00:00.0 / 01:25.6) | อ่านตลอด | ตอนนี้อยู่กลาง ซ่อนที่จอแคบ |

## กติกาที่ห้ามแหก

- **ห้ามลบฟีเจอร์** ย้าย/ยุบ/ซ่อนใต้เมนูได้ แต่ต้องยังกดถึงได้ทุกอัน
- **ห้ามปุ่มหลอก** ปุ่มที่กดแล้วไม่เกิดอะไรถือว่าไม่มี
- ตัวอักษรต่ำสุด 12px · ปุ่มสูงต่ำสุด 36px (ไอคอนเดี่ยวต้อง 36×36) · checkbox 18px
- สีเน้น terracotta `#D97757` **ใช้กับ primary action เท่านั้น** ห้ามใช้ตกแต่ง
- destructive (ลบ) ต้องแยกสายตาออกจากปุ่มปกติ และต้องมียืนยันก่อนลบ (มีแล้ว ห้ามถอด)
- ทำงานได้ตั้งแต่ **กว้าง 500px** (หน้าต่างแคบข้างจอ) ถึง **1920px**
- header สูงไม่เกิน 56px ที่จอปกติ — พื้นที่ที่เหลือเป็นของไทม์ไลน์กับพรีวิว
- ต้องบอกได้ตลอดว่า **กำลังแก้โปรเจกต์ไหน** แม้จอแคบ
- เมนูนี้ซ่อน Topbar ของแอป ตัวเลือกขนาดตัวอักษรจึงต้องเข้าถึงได้จากที่นี่

## สิ่งที่ต้องส่งมอบ

**ส่วนที่ 1 — เสนอ 2-3 แบบ พร้อมภาพ ASCII ที่ 3 ความกว้าง (500 / 1280 / 1920)**
แต่ละแบบบอก: จัดกลุ่มยังไง · อะไรยุบเข้าเมนู `⋯` · อะไรย้ายออกจาก header ไปอยู่ที่อื่น · ข้อเสียคืออะไร

**ส่วนที่ 2 — เลือก 1 แบบพร้อมเหตุผล** อ้างหลักการที่ใช้ (ลำดับความสำคัญ / การจัดกลุ่ม / progressive disclosure) ไม่ใช่ความชอบ

**ส่วนที่ 3 — แผนลงมือ** บอกว่าจะแก้บรรทัดไหนของ EditorShell.jsx · ต้องแตะไฟล์อื่นไหม · แบ่ง commit ยังไง

**ยังไม่ต้องเขียนโค้ด** จนกว่าจะเลือกแบบเสร็จ

## เกณฑ์ตรวจหลังทำ (วัดด้วยเบราว์เซอร์จริง ห้ามเดา)

1. ที่ 500px: คอนโทรลกินไม่เกิน **60%** ของความกว้าง header (ตอนนี้ 84%)
2. ที่ 500px: ชื่อโปรเจกต์ที่กำลังแก้ **อ่านออกอย่างน้อย 12 ตัวอักษร** (ตอนนี้ 37px = อ่านไม่ออก)
3. ปุ่มเรนเดอร์ **ไม่ถูกอะไรทับ** ทุกความกว้าง และเป็นของที่เด่นที่สุดในแถบ
4. ทุกฟีเจอร์เดิมยังกดถึงได้ (ไล่เช็คทีละอันจากตารางข้างบน)
5. ปุ่มทุกตัว ≥36px · ตัวอักษรทุกตัว ≥12px · มี focus ring ครบ
6. ที่ 1280×800 ไทม์ไลน์ยังครบ 3 แทร็ก พรีวิวไม่เล็กลงกว่าเดิม (ปัจจุบัน 253×451)
7. ไม่มี horizontal scroll ทุกความกว้าง · console 0 error
8. `npm run build` ผ่าน · `python -m pytest scripts/test_phase1_smoke.py` 100 ตัวผ่าน
