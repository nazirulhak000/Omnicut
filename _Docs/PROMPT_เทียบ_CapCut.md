# พรอมพ์เทียบงานกับ CapCut ของจริง — หาว่ายังขาดอะไร

วิธีใช้: copy บล็อกด้านล่างวางในแชท. ใช้ตอนอยากรู้ว่า "เมนูตัดต่อมือ" ห่างจาก CapCut จริงแค่ไหน และอะไรที่ทำไม่ได้เพราะข้อจำกัดเครื่อง/กฎ ไม่ใช่เพราะยังไม่ได้ทำ

---

## บล็อกสำหรับ copy

```
เทียบเมนู "ตัดต่อมือ" (frontend/src/components/editor/ + scripts/video_editor.py) กับ CapCut desktop ของจริง ทีละฟีเจอร์ แล้วบอกว่ายังขาดอะไร

กติกา (สำคัญกว่ารายการ):
- ห้ามตอบว่า "มีแล้ว" จากการเดา ต้องชี้ file:line ที่ทำงานจริง + เปิดเบราว์เซอร์กดดูจริงว่ามันทำงาน ไม่ใช่แค่มีปุ่ม
- ห้ามตอบว่า "ทำได้" ถ้า ffmpeg ฝั่ง backend ยังไม่รองรับ ให้แยกให้ชัดว่า "UI มีแต่ backend ไม่มี" คือยังไม่มี
- อะไรที่ทำไม่ได้เพราะข้อจำกัดจริง ให้บอกข้อจำกัดนั้นตรงๆ ไม่ต้องเสนอทางอ้อมที่ผิดกฎ:
  * เครื่องนี้ CPU-only (AMD ไม่มี CUDA) เข้ารหัส libx264 อย่างเดียว
  * ห้ามโหลด/ใช้เพลงลิขสิทธิ์จาก TikTok — royalty-free เท่านั้น
  * ห้าม scrape TikTok/Shopee เกิน public og:/oEmbed metadata
  * คนใช้เขียนโค้ดไม่เป็น ทุกฟีเจอร์ต้องกดได้จาก UI
- ประเมินแรงเป็น "ชั่วโมงคน" คร่าวๆ (S = <2 ชม, M = ครึ่งวัน, L = 1-2 วัน, XL = เกินนั้น)

ให้ไล่ตามโครงเมนูของ CapCut จริง:

A. Media / คลิป
   นำเข้าไฟล์ · ลากลงไทม์ไลน์ · ตัด (split) · ลบ · ทำสำเนา · เรียงลำดับ · trim ขอบ ·
   ความเร็ว (คงที่ / curve) · ย้อนกลับ (reverse) · หยุดเฟรม (freeze) · กลับซ้ายขวา · หมุน ·
   ครอป · zoom/pan ในเฟรม · ปรับขนาด+ตำแหน่งบนจอ · ลบพื้นหลัง (auto cutout) · chroma key

B. เสียง
   แยกเสียงออกจากวิดีโอ · ปรับ volume ต่อคลิป · fade in/out · auto-ducking จริง ·
   waveform บนไทม์ไลน์ · ตัดเสียงตามจังหวะ (beat detect) · เปลี่ยนเสียง (voice changer) ·
   เพลงประกอบ · SFX · ปรับ pitch/speed ของเสียง

C. ข้อความ / คำบรรยาย
   เพิ่มกล่องข้อความอิสระ · ลากวางตำแหน่งเอง · ฟอนต์/ขนาด/สี/ขอบ/เงา/พื้นหลัง ·
   อนิเมชันเข้า-ออก · ซับอัตโนมัติจากเสียง · แก้ซับทีละท่อน · แปลภาษา ·
   text-to-speech · เทมเพลตข้อความสำเร็จรูป

D. สติกเกอร์ / เอฟเฟกต์
   สติกเกอร์วางอิสระ · อนิเมชันสติกเกอร์ · เอฟเฟกต์ภาพ (glitch/blur/zoom) ·
   เอฟเฟกต์บนตัว (body effect) · overlay/PiP ซ้อนวิดีโอหลายชั้น

E. รอยต่อ / ฟิลเตอร์ / สี
   transition กี่แบบ (CapCut มี ~50, เรามีกี่แบบ) · ปรับความยาว transition ได้ไหม ·
   ฟิลเตอร์สำเร็จรูป · ความเข้มฟิลเตอร์ · ปรับสีเอง (brightness/contrast/saturation/temp) ·
   LUT · keyframe ของค่าใดๆ

F. ไทม์ไลน์ / การทำงาน
   หลายแทร็ก · ล็อกแทร็ก · ซ่อนแทร็ก · snap · magnetic timeline · zoom ·
   undo/redo · คีย์ลัด · พรีวิวเต็มจอ · marker · ripple delete · คัดลอกคุณสมบัติ

G. ส่งออก
   เลือกความละเอียด/fps/bitrate · เลือกสัดส่วน (9:16 / 1:1 / 16:9) · ส่งออกช่วงที่เลือก ·
   ลายน้ำ · เวลาเรนเดอร์จริงบนเครื่องนี้

ตอบเป็น 3 ส่วน:

ส่วนที่ 1 — ตารางเทียบทุกข้อข้างบน
| ฟีเจอร์ CapCut | ของเรา (มี / มีครึ่งเดียว / ไม่มี) | หลักฐาน file:line หรือผลกดจริง | backend ffmpeg รองรับไหม | แรง | ควรทำไหม |

ส่วนที่ 2 — จัดกลุ่มสิ่งที่ยังขาด เป็น 4 กอง
  1. ขาดแต่ทำได้ง่ายและคุ้ม (ทำเลย)
  2. ขาดและต้องแก้ backend ด้วย (วางแผนก่อน)
  3. ทำได้แต่ไม่คุ้มกับเครื่อง CPU-only (บอกเวลาเรนเดอร์ที่จะเพิ่มขึ้น)
  4. ทำไม่ได้/ไม่ควรทำ (บอกเหตุผล: ลิขสิทธิ์ / ToS / ต้องใช้ GPU / ต้องใช้ AI model ที่เครื่องรันไม่ไหว)

ส่วนที่ 3 — 10 อันดับที่ควรทำต่อ เรียงตามผลกับงานจริง
งานจริงคือ: คลิปรีวิวสินค้า TikTok Shop affiliate แนวตั้ง 9:16 ยาว 30-90 วิ ทำวันละ 2 ชม
แต่ละอันดับบอก: ทำอะไร · ได้อะไรเพิ่ม · แรงเท่าไหร่ · เสี่ยงตรงไหน
อันไหนที่ CapCut มีแต่ "คลิปรีวิวสินค้าไม่ได้ใช้" ให้บอกว่าไม่ต้องทำ พร้อมเหตุผล

ปิดท้ายด้วยประโยคเดียว: ตอนนี้เมนูนี้เท่ากับ CapCut กี่ % สำหรับงานรีวิวสินค้า (ไม่ใช่ % ของฟีเจอร์ทั้งหมดของ CapCut)
```

## เวอร์ชันสั้น (ถามเฉพาะช่องว่างที่สำคัญ)

```
เทียบเมนูตัดต่อมือกับ CapCut เฉพาะที่คลิปรีวิวสินค้า TikTok ใช้จริง:
ตัด/เรียง/trim/speed/transition/ซับ/เพลง/สติกเกอร์/ฟิลเตอร์/ส่งออก
บอกมาเป็นตาราง: อันไหนมี อันไหนมีครึ่งเดียว อันไหนไม่มี — พร้อม file:line และผลกดจริง
แล้วสรุป 5 อันดับที่ควรทำต่อ พร้อมแรงที่ต้องใช้
ห้ามเดา ห้ามนับปุ่มที่ backend ยังทำไม่ได้ว่า "มีแล้ว"
```

## สิ่งที่รู้อยู่แล้วว่ายังไม่มี (ตกลงกันไว้ ไม่ต้องรื้อถามใหม่)

ให้ audit ยืนยันว่ายังเป็นแบบนี้อยู่ และประเมินใหม่ว่าคุ้มจะทำหรือยัง:

| ยังไม่มี | เหตุผลที่ยังไม่ทำ |
|---|---|
| multi-track ซ้อนวิดีโอ (overlay/PiP) | ต้องเพิ่ม ffmpeg overlay pass รอบสอง |
| keyframe / color curve | ขอบเขตรอบแรกไม่รวม |
| reverse / freeze frame | reverse ต้อง decode ทั้งคลิปเข้า RAM — CPU-only 13.7GB เสี่ยง |
| waveform เสียงจริงบนไทม์ไลน์ | ต้อง decode ผ่าน Web Audio API |
| วางตำแหน่ง text/sticker เองบนจอ | backend ยังวาง sticker มุมขวาบนอย่างเดียว |
| auto-ducking จริง | ตอนนี้เป็น bgm_vol คงที่ 0.12 (≈ -18dB) ไม่ใช่ ducking ตามเสียงพูด |
| LUT | มีแต่ทำให้เวลาเรนเดอร์เพิ่ม ~90% เลยเป็น opt-in |

## บริบทเครื่อง (ให้ audit ใช้ประเมินแรง/เวลา)

- CPU-only, AMD Radeon ไม่มี CUDA → libx264 preset ปกติ
- คลิปทดสอบจริง: esseger 85.6s / IMG_1825 29.2s
- เรนเดอร์ล่าสุดที่วัดได้: video 13.6s + เสียง 28.3s → ไฟล์ 15.15 MB
- filmstrip: ครั้งแรก ~5 วิ, cache ~0.2 วิ
