# Prompt: ตรวจระบบ OmniCut + เทียบ CapCut เพื่อพัฒนาฟีเจอร์

ไฟล์นี้เป็น prompt สำหรับ AI coding agent (Codex, Antigravity, Claude Code) ให้ชี้มาที่ไฟล์นี้แล้วสั่ง "ทำตามไฟล์นี้"
รอบนี้เป็นงานตรวจและวางแผนเท่านั้น ยังไม่แก้โค้ด

---

## เป้าหมาย

ตรวจโปรแกรม OmniCut Pro Studio ที่มีอยู่ตอนนี้ แล้วเสนอ "ฟีเจอร์ใหม่" และ "จุดที่ปรับปรุงของเดิมได้" เรียงตามความคุ้มค่า
โดยใช้ CapCut (PC) เป็น reference เพื่อหาฟีเจอร์ที่เขามีแล้วเรายังไม่มี หรือมีแต่ใช้ยากกว่า

## ขั้นเตรียม (บังคับ ตาม AGENTS.md)

1. อ่าน TODO.md (ดูไม่เกิน 100 บรรทัด ห้ามเปิด HISTORY.md ทั้งไฟล์) ดูว่ารอบก่อนค้างอะไร
2. รัน `git status` ดูงานค้างใน working tree อย่าไปทับงานคนอื่น
3. อ่าน ARCHITECTURE.md เพื่อเข้าใจโครงสร้างจริง ก่อนสรุปอะไร
4. เขียนแผนรอบนี้ลง TODO.md ก่อนเริ่ม ระบุ `ดำเนินการโดย: <เอเจนต์> (<โมเดล>)`

## ขอบเขตที่ต้องตรวจ

- **Pipeline ผลิตคลิป 9:16:** scripts/pipeline.py, stages/, subtitle_engine.py, TTS, J-Cut, shot matching
- **Editor (frontend):** SequencePlayer.jsx, EditorShell.jsx, AssetPanel.jsx, editorProjectState.js

- **Tools และ Audit:** tools/*audit*.py, backup/restore
- **Test:** ช่องว่างที่ยังไม่มี test ตาม .agents/rules/testing_standard.md

## สิ่งที่ต้องหา

1. **ปัญหาเดิม:** bug เสี่ยง, โค้ดซ้ำ, จุดช้า, ขั้นตอนที่ต้องทำมือซ้ำๆ, UX ที่ขัด, preview ไม่ตรง render (ดู .agents/rules/preview_render_parity.md)
2. **ฟีเจอร์ใหม่:** ที่ลดเวลาผลิตคลิป เพิ่มคุณภาพ หรือเพิ่มยอดดูบน TikTok (hook, retention, A/B, วิเคราะห์ผลหลังโพสต์ ฯลฯ)
3. **ความเสี่ยงข้อมูล:** จุดที่อาจลบหรือทับ 01_Raw/, 02_Assets/, draft CapCut โดยไม่มี backup

## ส่วนเทียบกับ CapCut

### วิธีหาข้อมูล CapCut

1. ดูจากสิ่งที่มีในเครื่องและโปรเจกต์เท่านั้น: โครงสร้าง `draft_content.json` (เปิดจากสำเนาที่ copy ไว้ ห้ามเปิดไฟล์จริงเพื่อแก้),
   ชนิด track/segment/effect/transition/keyframe ที่เจอจริง, โค้ดส่วนที่เราเขียนคุยกับ draft อยู่แล้ว (ดูใน ARCHITECTURE.md)
2. ฟีเจอร์ของ CapCut ที่ไม่ได้อยู่ในไฟล์ให้ระบุว่า "ยังไม่ได้ยืนยัน" ห้ามเดาว่ามี และห้ามเขียนเหมือนรู้แน่
3. ถ้าต้องหาข้อมูลเพิ่มจากเว็บ ให้ระบุแหล่งที่มาทุกข้อ

### ฟีเจอร์กลุ่มที่ควรเทียบ

- ซับ: auto caption, ปรับสไตล์/แอนิเมชัน, แปลซับ (เทียบกับ Micro-Burst และ Ghost Reveal ของเรา)
- เสียง: ตัดเสียงเงียบ, ลดเสียงรบกวน, beat sync, ปรับเสียงอัตโนมัติ
- ภาพ: ตัดพื้นหลัง, tracking, keyframe, speed ramp, transition, effect, LUT/สีอัตโนมัติ
- ตัดต่ออัตโนมัติ: auto-cut, ตัดตาม beat, template, ตัดช่วงเงียบ
- Workflow: batch export, preset, proxy/cache, undo/history, shortcut

## รูปแบบผลลัพธ์

บันทึกรายงานที่ `_Docs/Plans/` (ห้ามวางที่รากโปรเจกต์) ประกอบด้วย 2 ตาราง

**ตาราง 1: ปัญหาเดิมและฟีเจอร์ใหม่**

| # | หัวข้อ | ประเภท (แก้/ใหม่) | ปัญหา/โอกาส | หลักฐาน (ไฟล์:บรรทัด) | ผลที่ได้ | แรง (S/M/L) | ความเสี่ยง |
|---|---|---|---|---|---|---|---|

**ตาราง 2: เทียบ CapCut**

| ฟีเจอร์ CapCut | OmniCut มีหรือยัง | ช่องว่าง | วิธีทำในระบบเรา (ใช้โมดูลไหน) | แรง (S/M/L) | ยืนยันแล้วหรือยัง |
|---|---|---|---|---|---|

กติกา:
- ทุกข้อต้องมีหลักฐานจากโค้ดจริง ห้ามเดา ถ้าไม่ได้เปิดดูให้ระบุว่า "ยังไม่ได้ยืนยัน"
- เลือก 5 อันดับแรกที่ควรทำก่อน พร้อมเหตุผลสั้นๆ และลำดับการทำ
- ระบุไฟล์ที่ต้องแตะ และ test ที่ต้องเพิ่มต่อข้อ

## ข้อห้ามระหว่างตรวจ

- ห้ามเปลี่ยนฟอนต์/ซับ/safe zone (.agents/rules/font_text_visual_contract.md)
- ห้ามสร้างไฟล์ทดสอบค้างใน 04_Exports/ และห้ามรันคำสั่งทำลายล้าง
- ห้าม hardcode absolute path
- ห้ามแก้ `draft_content.json` หรือ `.cloud_cache_*` ของ CapCut โดยไม่ backup
- ห้ามคัดลอกโค้ด ไฟล์ effect หรือ asset ที่เป็นของ CapCut ไปใส่โปรเจกต์ ให้เสนอวิธีทำเองจากพฤติกรรมที่เห็น
- ห้ามติดตั้งอะไร global นอก `.venv` และ `requirements.txt`
- ฟีเจอร์ที่เสนอต้องคงสเปก 1080x1920, 30 FPS และกฎซับ/ฟอนต์เดิม
- ถ้าจะใช้ `tools/jev_advisor.py` ให้ใช้ตอนเจอทางเลือก 3–7 อัน ถ้า confidence < 0.80 ให้หยุดถามผู้ใช้
