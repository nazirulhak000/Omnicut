## 1. สิ่งที่พบ

1. **ทุกขั้นมี endpoint ครบ และส่วนใหญ่มีแบบทำทั้งชุดอยู่แล้ว** (สคริปต์, เสียง, ดราฟต์, เรนเดอร์, เติมคิว) สิ่งที่กินเวลาคือคนต้องกดเชื่อมแต่ละขั้นเอง ข้าม 4 หน้าจอ
2. **ไม่มีจุดไหนสร้างปกให้เอง** — หลังเรนเดอร์เสร็จ ระบบแค่บันทึก export กับสถานะมุม ([batch_render.py](../../scripts/batch_render.py) `_process_item`, [api_render.py:254-276](../../scripts/api_render.py#L254-L276), [render_jobs.py](../../scripts/render_jobs.py) `complete_job`)
3. **Editor บังคับให้บันทึกปกก่อน ถึงจะกด Render ได้** ([EditorShell.jsx:2261-2268](../../frontend/src/components/editor/EditorShell.jsx#L2261-L2268)) — ทุกคลิปที่เรนเดอร์จาก Editor ต้องกด "ปก" → บันทึก → แล้วค่อย Render
4. **เรนเดอร์หลายมุม (BatchRenderModal) ไม่มีด่านปก** → คลิปออกมาไม่มีปก ต้องเปิด Cover Studio ทีละคลิปภายหลัง และคิวโพสต์รับคลิปที่ไม่มีปกได้ (ปกเป็นช่องไม่บังคับใน [api_schedule_queue.py](../../scripts/api_schedule_queue.py) `_build_record`)
5. **ตัวเลือกเฟรมปกอัตโนมัติมีอยู่แล้ว** แต่ถูกเรียกเฉพาะตอนเปิด Cover Studio: `recommended_cover_timestamp()` ใน [api_covers.py:253](../../scripts/api_covers.py#L253) เลือกเฟรมที่คมที่สุดในช่วงที่ป้าย Hook อยู่บนจอ
6. **แคปชัน/แฮชแท็กไม่ต้องทำเพิ่ม** — ติดมากับมุมตั้งแต่ตอนสร้างสคริปต์ (`tiktok_caption`, `tiktok_hashtags`)
7. **`/api/command/execute` ใช้เป็นตัวสั่งงานต่อเนื่องไม่ได้** — งานผลิตจริงแค่ตอบ "เข้าคิวแล้ว" โดยไม่ได้รันอะไร ([api_command.py:433-444](../../scripts/api_command.py#L433-L444))

## 3. ข้อเสนอ

### A. ปกอัตโนมัติหลังเรนเดอร์ (แนะนำทำก่อน — เล็กสุด ได้ผลทุกคลิป)

- **ทำอะไร:** ฟังก์ชันเดียว "ถ้า export นี้ยังไม่มีปก ให้สร้างปกเริ่มต้น" เรียกหลังเรนเดอร์สำเร็จทั้งสองทาง (ชุด และ Editor)
- **ปกที่ได้:** เฟรมจาก `recommended_cover_timestamp()` → `render_pro_cover(aspect_ratio="both", enable_hook_text=False)` → ผูกกับ export ด้วย `ExportCoverBindingStore.save` + เขียนช่องปกของมุม — ผลเท่ากับเปิด Cover Studio แล้วกดบันทึกด้วยค่าเริ่มต้นที่ใช้อยู่ทุกวันนี้ (ได้ทั้ง 9:16 และ 3:4)
- **กติกา:**
  - ไม่เขียนทับปกที่คนเลือกเอง
  - ปกที่ระบบสร้างเองติดป้าย `auto` — เรนเดอร์ซ้ำแล้วสร้างใหม่ได้ (เฟรมอาจเปลี่ยน) และ UI แสดงว่าเป็นปกอัตโนมัติให้กดเปลี่ยนได้
  - สร้างปกไม่สำเร็จ ≠ เรนเดอร์ล้ม — บันทึก log แล้วคลิปอยู่สถานะไม่มีปกเหมือนทุกวันนี้
  - ทำในงานเดียวกับเรนเดอร์ ไม่เปิดงานขนานเพิ่ม (ข้อจำกัด RAM 4 งาน)
- **ด่านปกใน Editor:** เปลี่ยนจาก "ไม่มีปก = ห้าม Render" เป็น "ไม่มีปก = Render ได้ แล้วระบบสร้างปกให้" — เป้าเดิมของด่าน (ทุกคลิปต้องมีปก) ยังอยู่ครบ
- **ไฟล์ที่แตะ (คาด):** ไฟล์ใหม่ `scripts/auto_cover.py`, จุดเรียกใน `batch_render.py` + `api_render.py`, ด่านใน `EditorShell.jsx`, ป้ายใน UI ปก, เทสต์ใหม่ (offline, temp storage)

### B. ปุ่มเดียวต่อสินค้า

- **B1 (แนะนำ) — สองปุ่ม มีจุดให้คนตรวจคั่นกลาง:**
  1. `ผลิตถึงดราฟต์` = เสียงทุกมุม → ดราฟต์ทุกมุม แล้วหยุดให้ตรวจใน Editor
  2. `เรนเดอร์และเข้าคิว` = เรนเดอร์มุมที่ยังไม่เรนเดอร์ → ปกอัตโนมัติ (ข้อ A) → เปิดพรีวิวเติมคิวให้กดยืนยัน
- **B2 — ปุ่มเดียวจบถึงพรีวิวคิว ไม่หยุดให้ตรวจดราฟต์:** เร็วสุด แต่ดราฟต์ที่ผิดจะถูกเรนเดอร์ทิ้งทั้งชุด และขัดกับกฎตรวจด้วยตาก่อนส่งงาน
- **วิธีทำ:** ตัวสั่งงานฝั่ง backend (งานใหม่บน `TaskManager`) เรียกของเดิมต่อกัน — เสียงชุด (เป็น background task อยู่แล้ว) → `BatchRenderManager.create_batch` — ปิดหน้าเว็บ/รีเฟรชแล้วงานยังเดินต่อ ถ้าทำฝั่งหน้าเว็บอย่างเดียวจะหลุดเมื่อรีเฟรช
- **ไฟล์ที่แตะ (คาด):** ไฟล์ใหม่ `scripts/production_chain.py` + endpoint ใหม่ 1 ตัว, ปุ่มใน `ProductToClip.jsx`, เทสต์ backend + เทสต์ UI (`tests/motion_capture` + dev server ตามกฎข้อ 26)
- **ต้องมี A ก่อน** ไม่งั้นปุ่มที่สองได้คลิปไม่มีปกเข้าคิว

### C. ของเล็ก

- **C1. ปุ่ม `เตรียมทั้งหมด` ในตารางโพสต์** — วนเรียก `/{item_id}/prepare` ของเดิมให้ทุกรายการที่ถึงกำหนด แทนกดทีละรายการ
- **C2. ความคมชัด TikTok อัตโนมัติ** — ไฟล์คมชัดเป็น export ใหม่ และปกที่ผูกกับ export เดิม**ไม่ตามไป** ([api_exports.py:1520-1528](../../scripts/api_exports.py#L1520-L1528)) ถ้าจะทำอัตโนมัติต้องทำก่อนสร้างปก หรือคัดลอกการผูกปกไปด้วย — ขึ้นกับว่าเจ้าของใช้ขั้นนี้กับทุกคลิปหรือไม่

## 5. ความเสี่ยง

- **เฟรมปกอัตโนมัติไม่สวย** (เบลอ/ช่วงเปลี่ยนช็อต) — ตัวเลือกเฟรมคัดเฟรมคมสุดในช่วงป้าย Hook, ถ้าหาไม่ได้ถอยไปที่ 1.0 วิ, มีป้าย `auto` ให้คนเปลี่ยนได้ทุกเมื่อ
- **มาตรฐานปก Style 3B (กฎข้อ 23)** เป็นปกออกแบบ 3 ชั้น — ปกอัตโนมัติเป็น "เฟรมสะอาด" ไม่มีอีโมจิ/ลูกศร จึงไม่ผิดกฎ แต่ไม่ใช่ปกออกแบบ เจ้าของต้องรับได้ว่าค่าเริ่มต้นเป็นแบบนี้
- **ไม่แตะฟอนต์/ข้อความ (กฎข้อ 10)** — ปกอัตโนมัติปิดข้อความ Hook จึงไม่กระทบ
- **ไฟล์ทะเบียนกลาง** — การผูกปกเขียนผ่าน `mutate_cover_bindings` ที่มี lock อยู่แล้ว
- **Extension** — มีเอเจนต์อื่นกำลังแก้อยู่ (ไฟล์ค้างใน working tree) แผนนี้จึงไม่แตะ

## 6. สิ่งที่ยังไม่ได้ยืนยัน

- จำนวนคลิกในตารางข้อ 2 มาจากการอ่านโค้ด ยังไม่ได้นับบนหน้าจอจริง
- เวลาที่ปกอัตโนมัติเพิ่มต่อคลิป ยังไม่ได้วัด
- เรนเดอร์ซ้ำโปรเจกต์เดิมได้ `export_id` เดิมหรือใหม่ — มีผลกับกติกา "สร้างปก auto ใหม่"
- Extension ดึงรายการคลิปจากไหน และจำเป็นต้องกด "เตรียม" ก่อนทุกรายการหรือไม่ (มีผลกับ C1)
