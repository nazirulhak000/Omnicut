# แผน: นับคลิปที่ตั้งเวลาไว้บน TikTok จริง เพื่อคุมโควตา schedule (แผงข้าง extension)

ผู้สั่ง: เจ้าของโปรเจกต์ (2026-11-10) · ดำเนินการโดย: Claude Code (Claude Sonnet 5.5)

## 1. ปัญหา (ยืนยันจากรูปแผงข้างของผู้ใช้ + หน้า Content จริง)
- ปุ่ม "เช็กโควตาสด" (`quota_detector.js`) อ่านเลขจากแท็บบนหน้า Studio > Content ("กำหนดเวลาแล้ว (N)" / "แบบร่าง (N)")
- หน้า Content ปัจจุบันมีแค่แท็บ "โพสต์ 217" และ "แบบร่าง 0" ไม่มีแท็บกำหนดเวลา → ค่า scheduled = null → แผงขึ้น `-- / 30`
- ผล: `getEffectiveBatchLimit` และ orchestrator (CHECK_QUOTA) ถือว่าว่าง 30 ทั้งที่ schedule ไปแล้ว ~15 → ไม่หยุดเองเมื่อใกล้เต็ม
- ตรรกะฝั่ง orchestrator ถูกอยู่แล้ว (หยุดเมื่อ remSched <= 0, คิด scheduleUsed ต่อคลิป) ขาดแค่ "ตัวเลข scheduledCount ที่ถูกต้อง"

## 2. แนวทาง
นับแถวในรายการหน้า Content ที่มีป้ายเวลา **ในอนาคต** (ป้ายนาฬิกาสีฟ้า) = คลิปที่ตั้งเวลาไว้
- แถวที่โพสต์แล้ว ป้ายเป็นเวลาในอดีต · แถวตั้งเวลา ป้ายเป็นเวลาในอนาคต
- รายการเรียงตามวันที่สร้าง (ใหม่สุดก่อน) โหลดทีละหน้า → เลื่อนโหลดเพิ่มจนเจอแถวที่ "โพสต์แล้ว และเก่ากว่า 31 วัน" (คลิปที่สร้างก่อนหน้านั้นไม่มีทางยัง schedule ค้าง เพราะ TikTok ตั้งล่วงหน้าได้ไม่เกิน 30 วัน) หรือครบเพดานแถว 400
- แถว "Pinned" ข้าม (ไม่ใช่คลิปตั้งเวลา)
- ป้ายเวลาที่รองรับ: อังกฤษ `Nov 10, 6:00 PM (GMT+7) Bangkok`, ไทย `10 พ.ย. 10:00 PM`, มีปี (ค.ศ./พ.ศ.), 24 ชม. · เขตเวลาอ่านจาก `(GMT+N)` ถ้าไม่มีใช้ +7 (ช่องนี้ Bangkok)

## 3. ขั้นตอนทำ
1. ฟังก์ชันบริสุทธิ์ใน `quota_detector.js`: `parseBadgeTime(text, now)`, `countScheduledFromListText(text, now)`, `applyScheduledCount(quota, count, options)` + unit test จากตัวอย่างจริงไทย/อังกฤษ
2. `background.js`: `runCountScheduledOnContent()` — ใช้แท็บ Studio ที่เปิดอยู่ (หน้า Upload/Content), ไป /content ผ่าน `navigateAcceptingLeave`, เลื่อนโหลด, อ่าน `document.body.innerText`, นับ, แล้วพาแท็บกลับหน้า Upload (เหมือน `runVerifyPostOnContent`)
3. `runDetectTikTokQuota`: ถ้าอ่านจากแท็บไม่ได้ค่า scheduled → เรียกข้อ 2 แล้วรวมผล (แหล่งที่มา `content_rows`)
4. แผงข้าง: ใช้ผลเดิม (ตัวเลขขึ้นจริง, ตัวจำกัดอัตโนมัติ = 30 − ตั้งเวลาแล้ว) + หลังจบรอบเรียกเช็กโควตาซ้ำ
5. เทส: unit (node) · เทียบกับหน้า Content จริง (นับจากคิว backend: scheduled_on_platform ที่เวลา > ตอนนี้ ต้องตรง ±คลิปที่ไม่ได้ลงด้วยคิว) · e2e แผงข้างจริง ดูค่า `ตั้งเวลา N / 30`
6. ยกเวอร์ชัน extension 0.3.9, อัปเดต TODO, ไม่แตะงาน session อื่นใน TODO.md

## 4. ความเสี่ยง/ข้อจำกัด
- โครงหน้า Content เปลี่ยนได้ → ถ้านับไม่ได้ (ไม่เจอแถวเลย) คืน null เหมือนเดิม ห้ามเดาเป็น 0
- เลข 30 เป็นค่าตั้งในโค้ด ยังไม่ได้ยืนยันกับเพดานจริงของ TikTok (ตั้งเป็นค่าคงที่เดียว `MAX_SCHEDULE_QUOTA`)
- การนำทางไปหน้า Content แล้วกลับ ใช้เวลา ~10–20 วินาทีต่อการเช็กหนึ่งครั้ง (เช็กตอนเริ่มรอบและเมื่อกดปุ่ม)
- แถวที่ตั้งเวลาไว้ในอดีตแต่ยังไม่เผยแพร่ (ล่าช้า) จะถูกนับเป็น "โพสต์แล้ว" ไม่นับเป็น schedule (ยอมรับได้ เพราะไม่กินโควตาล่วงหน้า)
