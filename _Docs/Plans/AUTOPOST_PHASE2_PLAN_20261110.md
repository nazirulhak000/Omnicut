## 2) งานใหม่ที่ผู้ใช้ขอ

### 2.A ระบบ ID คลิป (EP) — งานหลักของเฟสนี้

เป้าหมาย: รู้ว่าโพสต์ไปกี่คลิปจากระบบอัตโนมัติ และตามย้อนหลังด้วยเลขที่คนอ่านแล้วจำได้ เช่น `EP:1731`

**หลักการ (ห้ามผิด)**
1. ออกเลข **ครั้งเดียว ตอนคลิปเกิด/เข้าคิวครั้งแรก** เก็บถาวร ห้ามเดาย้อนหลังจาก TikTok ห้ามใช้ซ้ำ แม้แบบร่างถูกลบหรือจัดเวลาใหม่
2. ตัวนับต่อช่อง, atomic (กัน 2 กระบวนการออกเลขซ้ำ), ผ่าน lock เหมือน registry อื่น
3. เลขอยู่ใน payload ที่แช่แข็งของ job (เข้า fingerprint) เปลี่ยนกลางทางไม่ได้
4. ถ้าใส่เลขใน caption ต้องเป็นรูปที่ตัวกันเนื้อหาไม่จับเป็นราคา (แนะนำแฮชแท็ก `#EP1731`)

**ขั้นตอนเทคนิค**
| ขั้น | งาน | ไฟล์หลัก | ทดสอบ |
|---|---|---|---|
| A1 | ตัวนับ `episode_counter` ต่อช่อง (ไฟล์/ตารางเดียวกับ store อื่น, lock) + API ออกเลข idempotent ตาม export | `scripts/` ใหม่ + `export_registry.py` | ออกเลข 8 ตัวพร้อมกัน ไม่ซ้ำ; ออกซ้ำ export เดิมได้เลขเดิม; เลขไม่ย้อน |
| A2 | เติม `episode_no` ใน export record → queue row → posting job (payload แช่แข็ง) | `api_schedule_queue.py`, `api_tiktok_autopost.py`, `posting_jobs.py` | job เก่าไม่มีเลขยังทำงาน (compat); เปลี่ยนเลขกลางทางไม่ได้ |
| A3 | ตัวประกอบ caption: ต่อท้าย ` #EP{n}` แบบ idempotent (มีแล้วไม่เติม) ก่อนตัวกันเนื้อหา; นับโควตา 4000 ตัว/30 แฮชแท็กรวมเลข | `content_guard.py` + `post_guard.js` + fixture ร่วม | parity JS↔Python เคสใหม่: `#EP1731` ผ่าน, `EP:1731` ผ่าน, เลขคล้ายราคาไม่ถูกจับผิด |
| A4 | ตัวจับคู่ของ "ตรวจกับ TikTok"/verify ใช้เลข EP ก่อน (แม่น 100%) ถอยไปใช้ 20 ตัวอักษรแรกเมื่อไม่มีเลข | `background.js`, `draft_sync.js`, `post_guard.js` | caption สองอันขึ้นต้นเหมือนกันแต่ EP ต่างกัน = ไม่สับสน |
| A5 | แสดงเลขบนการ์ด/ประวัติรอบ/ชื่อ log; รายงาน "ผ่านระบบไปแล้ว N คลิป" ตามเลข/ช่วงเลข/ช่วงวัน | `sidepanel.js`, API รายงานใหม่ | แผงแสดงเลข; รายงานตรงกับจำนวน job สำเร็จ |
| A6 | เก็บเลขใน post log/stats import (จับคู่ตัวเลขดูวิวย้อนหลังด้วยเลข) | `post_log.py`, stats import | คลิปที่โพสต์ไปแล้วได้เลขตาม backfill |
| A7 | Backfill คลิปเดิม (156 โพสต์ + 22 ตั้งเวลา + คลิปในคลัง) ตามลำดับเวลาโพสต์ **โหมดดูตัวอย่างก่อนเขียน** | สคริปต์ใหม่ใน `tools/` | รันซ้ำได้ ผลเหมือนเดิม; ไม่แก้ caption บน TikTok ที่โพสต์ไปแล้ว |

**จุดที่ต้องระวัง**
- เลขใน caption ของโพสต์เก่าบน TikTok แก้ย้อนหลังไม่ได้ (และไม่ควร) การย้อนหลังของโพสต์เก่าอาศัย backfill ในระบบ ไม่ใช่ในตัวโพสต์
- ถ้าตัดสินใจไม่ใส่เลขใน caption: ยังรู้จำนวนโพสต์จากระบบได้ แต่ "ตรวจกับ TikTok" ใช้เลขจับคู่ไม่ได้
- caption ของแบบร่างที่บันทึกไปแล้วไม่มีเลข (ถ้าเริ่มใส่เลขทีหลัง) ต้องถือว่าเป็นกรณี legacy ใช้จับคู่แบบเดิม

### 2.B เก็บกวาดบัญชีและข้อมูลทดสอบ

- โพสต์ทดสอบจริงที่ผมสร้างบนบัญชี 7 โพสต์ (19, 20, 22×2 พ.ย. ตั้งเวลา; 11 พ.ย. 09:00/12:30; 10 พ.ย. 20:15 สด) — ผู้ใช้ตัดสินใจเก็บหรือลบ แล้วอัปเดตสถานะในคิว
- ทำเครื่องหมาย/ชื่อ "[TEST]" ให้ใช้ค้นหาแถวคิวทดสอบ และเพิ่มสคริปต์ล้างของทดสอบ (ไม่ลบอะไรบน TikTok เอง เหลือแต่ฝั่งระบบ)

### 2.C คลิปที่ติดตัวกัน caption ราคา

- exports ที่เหลือส่วนใหญ่มีคำว่า "ราคา/ลดราคา" ใน caption: **แก้ที่ต้นทาง (ตัวสร้าง caption)** ไม่ใช่ผ่อนตัวกัน
- งาน: หาจุดที่สร้าง `tiktok_caption`/`hook_title` แล้วให้ไม่สร้างคำต้องห้าม (ใช้ตัวกันเดียวกัน) + เครื่องมือสร้าง caption ใหม่ให้คลิปเก่า (ดูตัวอย่างก่อนบันทึก)
- ผลตามมา: ปลดล็อก G4 (ทดสอบ conductor จริง) และมีคลิปให้รันออโต้ต่อ

### 2.D หน้า scheduler หลักของโปรแกรม (React)

- แสดง `needs_reschedule`, ป้ายแบบร่าง, ปุ่มจัดเวลาใหม่ทั้งหมด, ปุ่มตรวจกับ TikTok ในหน้า `ScheduleAgenda.jsx`
- ข้อควรระวัง: ไฟล์ frontend มีงานของเอเจนต์อื่นค้างหลายไฟล์ ต้องประสานก่อน/ทำบนกิ่งแยก (ตามกฎข้อ 25 ใน AGENTS.md) และ build dist ใหม่
- ไม่กระทบความปลอดภัยของการโพสต์ (ทำภายหลังได้)

### 2.E เส้นทางหลักของงานไม่มีคนเฝ้า (ต้องตัดสินใจ)

- ตอนนี้ extension (แผงข้าง) มีครบ: แบบร่าง, จัดเวลาใหม่, ตรวจกับ TikTok, ประวัติ, แจ้งเตือน
- conductor (Node ไม่มีแผง) **ขาด** เผยแพร่จากแบบร่าง/จัดเวลาใหม่/ตรวจกับ TikTok
- ถ้าเลือก extension เป็นทางหลัก: ปิดงาน conductor เป็นเครื่องมือทดสอบ/สำรอง (ไม่ลงทุนเพิ่ม)
- ถ้าอยากไม่ต้องเปิดแผงทิ้งไว้: ต้องยก 3 ฟีเจอร์ไป conductor (งานก้อนใหญ่ ~ 1 รอบ)
