# 📦 แผนแม่บท: ระบบย้ายและสำรองข้อมูลคลิปที่โพสต์แล้ว (Posted Clips Archive & Storage Reclamation)

## 📌 บทนำและเป้าหมาย (Objective & Scope)
เมื่อมีการผลิตคลิปและโพสต์ลง TikTok อย่างต่อเนื่อง พื้นที่บนฮาร์ดดิสก์ของเครื่องคอมพิวเตอร์จะถูกใช้ไปอย่างรวดเร็ว โดยเฉพาะ:
1. **ไฟล์วิดีโอที่ Export แล้ว (`04_Exports/Posted/`):** แต่ละคลิปขนาดประมาณ 30–80 MB (ปัจจุบัน 8 คลิป = 316.4 MB)
2. **โฟลเดอร์โปรเจกต์งานตัดต่อ (`03_Projects/`):** ไฟล์ Audio WAV, Manifest, Draft cues (ปัจจุบัน 11 โปรเจกต์ที่โพสต์แล้ว = 182.6 MB)
3. **ฟุตเทจดิบ (`01_Raw/`):** วิดีโอต้นฉบับจากมือถือ/กล้อง ขนาดรวมกว่า 1.1 GB (เมื่อสินค้าตัวนั้นโพสต์ครบทุกมุมมองแล้ว)
4. **แคชดราฟต์ของ CapCut PC (`com.lveditor.draft/`):** ไฟล์พรีวิวและแคชตัดต่อในเครื่อง

**เป้าหมายของงานนี้:**
1. **ในหน้า UI (`AnalyticsHub` -> `พื้นที่จัดเก็บ & ระบบ`):** เพิ่มการ์ดสถิติและวิดเจ็ตแสดง:
   - จำนวนคลิปที่โพสต์แล้วทั้งหมด (Posted Clips Count)
   - พื้นที่ที่จะประหยัดได้ทันทีหากย้าย Backup ทั้งหมดออกไปยัง External Drive / Cloud Drive
   - ป้ายระบุรายละเอียด (Breakdown) ของไฟล์ที่พร้อมย้าย: วิดีโอ Export, โปรเจกต์ดราฟต์, และฟุตเทจดิบของสินค้าที่จบกระบวนการแล้ว
2. **สร้างพิมพ์เขียวสถาปัตยกรรม (Archive & Backup Pipeline Blueprint):** ออกแบบระบบย้ายและสำรองข้อมูลที่ปลอดภัย ไม่ทำให้ข้อมูลสูญหาย (Zero Data Loss) และยังสามารถติดตามประวัติและสถิติการขาย/ยอดวิวได้ครบถ้วน 100%

### 1.2 สิ่งที่ "ซ่อนจากสายตา แต่ยังดูย้อนหลังได้" (Hide in UI with Toggle)

### 1.3 สิ่งที่ "ห้ามลบและห้ามย้ายเด็ดขาด" (Strict Keep Local)

2. ❌ **`01_Raw/` ของสินค้าที่ยังมีมุมมองค้างอยู่:** สินค้าใดที่มี 7 มุมมอง แต่โพสต์ไปแค่ 2 มุมมอง ห้ามย้ายโฟลเดอร์ Raw ของสินค้านั้นเด็ดขาด เพื่อให้ทีมงานตัดต่อมุมมองที่เหลือต่อได้

## 🔒 2. กลไกความปลอดภัยและความถูกต้องของข้อมูล (Safety Guarantees)

1. **การตรวจสอบความสมบูรณ์ก่อนลบ (Verify-Before-Delete):**
   - เมื่อสั่งย้ายไฟล์ (เช่น `04_Exports/Posted/clip.mp4` -> `E:/OmniCut_Backup/04_Exports/Posted/clip.mp4`)
   - ระบบจะคำนวณ Hash (SHA-256 หรือ File Size Match) ที่ปลายทาง
   - จะลบไฟล์ต้นทางบนเครื่องคอมพิวเตอร์ **ก็ต่อเมื่อไฟล์ปลายทางเขียนเสร็จสมบูรณ์ 100% แล้วเท่านั้น**
2. **ระบบกู้คืนใน 1 คลิก (One-Click Restore):**
   - หากต้องการนำคลิปเก่ามา Re-post หรือเปิดดูซ้ำ สามารถกดปุ่ม **"กู้คืนเข้าเครื่อง (Restore to Local)"** ระบบจะดึงไฟล์จาก External Drive กลับมาวางในตำแหน่งเดิม
3. **การบันทึกตำแหน่งไฟล์สำรอง (Archive Manifest Registry):**
   - ใน `export_registry.json` จะอัปเดตฟิลด์ระบุ `archived: true` พร้อมเก็บ `archive_path` และวันเวลาที่สำรองข้อมูล

## 💻 3. แผนการพัฒนาในโค้ด (Proposed Implementation)

### 3.1 Backend: อัปเดต `scripts/api_analytics.py`
- เพิ่มการคำนวณใน `GET /api/analytics/storage`:
  - `posted_archive_potential`:
    - `posted_clips_count`: 8 คลิป
    - `posted_angles_count`: 11 มุมมอง
    - `posted_exports_bytes`: ~316.4 MB
    - `posted_projects_bytes`: ~182.6 MB
    - `completed_products_raw_bytes`: ขนาด Raw ของสินค้าที่โพสต์ครบแล้ว
    - `total_reclaimable_bytes`: รวมพื้นที่ที่ประหยัดได้ทันที (~500 MB ถึง 1.6 GB)
    - `total_reclaimable_gb`: ขนาดเป็น GB

### 3.2 Frontend: อัปเดต `StorageAnalyticsTab.jsx`
- เพิ่มการ์ดสถิติชุดใหม่ในหน้า Storage:
  - **การ์ด "คลิปที่โพสต์ & โอกาสประหยัดพื้นที่" (Posted Clips & Archive Potential):**
    - แสดงตัวเลขจำนวนคลิปที่โพสต์แล้ว (`8 คลิป`)
    - แสดงพื้นที่ที่จะได้คืนทันทีหากย้ายสำรอง (`~500 MB` ถึง `1.6 GB`)
    - แสดงสัดส่วนว่าคิดเป็นกี่ % ของพื้นที่โปรเจกต์ทั้งหมด
    - มีแท็กสรุปรายการ: `8 วิดีโอ MP4`, `11 โปรเจกต์ดราฟต์`
