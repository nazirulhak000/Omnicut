## แผน (เรียงตามคุณค่า — Jev เลือก P1 ก่อน ความมั่นใจ 0.73)

### P1 · แผงรายละเอียดมุม: ปุ่มหลักตามขั้นต่อไปเพียงปุ่มเดียว
- ปุ่มหลักเปลี่ยนตามสถานะของมุม
  - ยังไม่มีคลิป → `เลือกคลิป`
  - มีคลิปแล้ว → `ส่งเข้า Tracker`
  - มีดราฟต์ → `เปิดใน Editor`
  - เรนเดอร์แล้ว → `ดูคลิป`
- ปุ่มอื่นลดเป็นปุ่มรอง (ขอบบาง) และไม่แสดงปุ่มใหญ่สองปุ่มพร้อมกัน
- ตัดปุ่ม `เลือกคลิป (0)` ที่ซ้ำออก ให้จำนวนคลิปไปอยู่ในบรรทัดสถานะ "คลิปต้นที่แนบ"
- แถบล่างแสดงเฉพาะสถานะและปุ่ม ไม่ทวน hook อีกรอบ
- พฤติกรรมของแต่ละปุ่มคงเดิม เปลี่ยนแค่ว่าปุ่มไหนเด่นและอยู่ตรงไหน

### P2 · รายการมุมแบบแถวกระชับ
- หนึ่งแถว (~72px) ประกอบด้วย: เลข, ชื่อมุม 1 บรรทัด, hook 1 บรรทัดสีจาง และด้านขวาเป็นชิปสถานะที่มีคำกำกับ (บท / เสียง / ดราฟต์ / เรนเดอร์)
- ย้ายปุ่ม `สร้างแผนถ่าย` ไปไว้ในแผงรายละเอียด
- ชิป id แสดงเฉพาะในแผงรายละเอียด
- "ยังไม่ได้เลือกคลิป" ย่อเป็นไอคอนเตือนพร้อม `title`
- จอเดสก์ท็อปเห็นได้ราว 8–9 มุมแทน 4
- บนมือถือ hook จะกลับมาแสดง (ตอนนี้ไม่ขึ้น)

### P3 · ยุบแผงสถานะเป็นแถบความคืบหน้าบรรทัดเดียว
- ย้ายเข้าการ์ดแถบเครื่องมือล็อต เป็นแถบแบ่งช่วง: บท 6 · เสียง 1 · ฉาก 0 · คลิป 0 · ดราฟต์ 0 · โพสต์ 0 / 6
- ตัดหัวข้อ "พื้นที่ทำงานสคริปต์" และบรรทัดคำแนะนำ
- ตัด "โพสต์แล้ว" ที่ขึ้นซ้ำ
- ประหยัดพื้นที่ ~120px บนเดสก์ท็อป และ ~250px บนมือถือ

### P4 · มือถือ + หัวแผงรายละเอียด
- แถบ action ล่างติดกับก้นของแผงรายละเอียด (sticky ภายในแผง) ไม่ลอยทับรายการ
- พอแตะเลือกมุมบนมือถือ ให้เลื่อนลงไปที่แผงรายละเอียดเอง
- ย้ายปุ่ม `แก้ Hook + บทพูด` / `เพิ่มเติม` ขึ้นไปอยู่แถวเดียวกับชื่อมุม

## ขอบเขตและสิ่งที่ไม่แตะ
- ไม่เปลี่ยนฟอนต์ ขนาดตัวอักษร หรือ weight (กฎข้อ 10) เปลี่ยนแค่ตำแหน่ง ระยะห่าง และระดับความเด่นของปุ่ม
- ไม่เปลี่ยน API, ข้อมูล หรือสิ่งที่แต่ละปุ่มทำ
- ไม่แตะหน้า Tracker / Gallery / Editor ในรอบนี้
- Antigravity อาจกำลังแก้ไฟล์เดียวกันอยู่ ตอน stage ต้องแยก hunk เฉพาะของรอบนี้

## การทดสอบ
- เทสต์เบราว์เซอร์ใหม่ `tests/motion_capture/test_product_angle_area_browser.py`
  - แต่ละสถานะของมุมมีปุ่มหลักปุ่มเดียว
  - ไม่มีปุ่ม `เลือกคลิป` ซ้ำ
  - แถวในรายการแสดงชื่อและ hook
  - บนมือถือแถบ action ไม่ทับรายการ
- ปรับเทสต์เดิมที่อ้างข้อความหรือปุ่มที่ย้ายที่ไป
- `node --test` + `npx oxlint` + `pytest tests/motion_capture` + ลองบน dev server + เปิดแอปที่ build แล้วเพื่อดูภาพหน้าจอเดสก์ท็อปและมือถือ

### P5 · จอกว้าง ≥1536px: เพิ่มคอลัมน์ข้าง (เจ้าของขอเพิ่มระหว่างทำ 2026-11-12 พร้อมภาพจอ 1920px)
- บทพูดสั้น ทำให้แผงรายละเอียดเหลือที่ว่างทางขวาเยอะ
- บนจอกว้างแบ่งแผงเป็นสองช่อง
  - ช่องหลัก: Hook และบทพูด
  - คอลัมน์ข้าง 320px: ปุ่มขั้นต่อไปอยู่บนสุด (ไม่ sticky) ตามด้วยเสียงนำถ่ายและคลิปดิบ
- จอแคบกว่า 1536px ยังเป็นช่องเดียว แต่ย้ายแถวเสียงนำถ่ายมาอยู่ใต้บทพูด ติดกับคลิปดิบ

## สิ่งที่ปรับจากแผนตอนลงมือ
- P1 ปุ่มหลักตามสถานะของมุม
  - ยังไม่มีคลิป → `เลือกคลิป`
  - ยังไม่มีเสียง → `เตรียมเสียงและแผนถ่าย`
  - พร้อมแล้ว → `สร้างดราฟต์`
  - มีดราฟต์ → `เปิดทำต่อใน Editor`
  - เรนเดอร์หรือโพสต์แล้ว → `ดูคลิป`
- `ส่งเข้า Tracker` เป็นปุ่มรองทุกสถานะ เพราะปุ่มนี้แค่พาไปหน้า Tracker ไม่ได้ทำขั้นผลิตให้มุมเดินต่อ
- ลอจิกอยู่ที่ `frontend/src/lib/angleNextStep.js` และมีเทสต์
- หัวแผงเคยใช้คลาส `xs:` ซึ่ง Tailwind v4 ของโปรเจกต์ไม่มี ทำให้หัวแผงเป็นสองแถวเสมอ เปลี่ยนเป็น `flex-wrap` แล้ว
