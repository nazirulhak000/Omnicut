# คู่มืออ่านค่าคอมและกราฟสินค้า TikTok Shop Affiliate ผ่าน ADB

ตรวจขั้นตอนบนมือถือ Android ที่เชื่อม ADB จริงเมื่อ 2026-10-13 หน้าตาแอปและตำแหน่งปุ่มอาจเปลี่ยนตามรุ่นมือถือหรือเวอร์ชัน TikTok ให้ดูข้อความและปุ่มบนจอก่อนใช้พิกัดตัวอย่าง

## 1. เข้าหน้าข้อมูลสินค้า

1. เปิด TikTok Shop Creator/Affiliate แล้วเข้าหน้า **สินค้าที่ต้องการตรวจ** ตรวจชื่อสินค้าและตัวเลือกสินค้าให้ตรงกับรายการที่จะโปรโมต
2. ที่แถบด้านล่างของหน้าสินค้า อ่าน **Earn ฿… per sale** แล้วบันทึกเป็นค่าคอมที่แอปแสดง ณ เวลาตรวจ พร้อมราคาที่แสดงและชื่อ/รุ่นสินค้า ค่าคอมที่จ่ายจริงอาจเปลี่ยนตามราคาที่ลูกค้าจ่ายและการคืนสินค้า อย่าใช้ยอดขายสะสมตลอดอายุสินค้าแทนยอดช่วงล่าสุด
3. กด **ลูกศรคู่ชี้ขึ้น** ตรงกึ่งกลางขอบบนของแถบด้านล่าง หน้าต่าง **Promotion info** จะเปิดขึ้น ถ้ากราฟยังไม่อยู่ในจอ ให้เลื่อนในหน้าต่างนี้ลงเล็กน้อยจนเห็นหัวข้อ **Product trends**
4. บันทึกวันที่ตรวจและช่วงวันที่ที่แอปแสดง เลือก **Last 7 days** และ **Last 30 days** จากเมนูช่วงเวลา แล้วอ่านค่าของแต่ละช่วงแยกกัน
5. กดไอคอน `i` ข้าง Product trends เพื่อดูคำอธิบายตัวชี้วัด แอประบุว่าใช้ **UTC+0** สำหรับตัวเลือกวันที่ ดังนั้นวันที่บนจออาจต่างจากวันตามเวลาไทย

ตัวชี้วัดที่เห็นจริง: **Orders** = จำนวนคำสั่งซื้อในช่วงที่เลือก; **CTR** = สัดส่วนผู้เห็นลิงก์แล้วคลิก; **Number of creators** = จำนวนครีเอเตอร์ที่สร้างการแสดงผลให้สินค้า; **Add-to-cart users** = จำนวนผู้เพิ่มสินค้าลงตะกร้าในช่วงนั้น

## 2. ใช้ ADB อ่านและบันทึกหน้าจอ

เปิด PowerShell จากรากโปรเจกต์ แล้วเช็กว่าเห็นมือถือหนึ่งเครื่อง:

```powershell
adb devices
adb shell wm size
```

ควบคุมการแตะหรือเลื่อนด้วย ADB ได้เมื่อเห็นตำแหน่งปุ่มบนหน้าจอแล้ว ตัวอย่างนี้ทดสอบกับจอ `1080x2400` และมีไว้แสดงรูปแบบคำสั่ง พิกัดจริงต้องปรับตามจอปัจจุบัน:

```powershell
adb shell input tap 540 1897
adb shell input swipe 540 1550 540 900 350
```

คำสั่งแรกแตะลูกศรคู่ชี้ขึ้นบนแถบล่างของหน้าสินค้าตัวอย่าง คำสั่งที่สองเลื่อนภายใน Promotion info เล็กน้อย ถ้ามีหลายเครื่อง ให้ระบุ serial จาก `adb devices` ด้วย `adb -s <serial> ...` ทุกคำสั่ง

ใน Windows PowerShell ให้จับภาพแบบไบนารีด้วยโค้ดนี้ เพราะการใช้ `adb exec-out screencap -p > ชื่อไฟล์.png` อาจทำให้ PNG เสียได้:

```powershell
New-Item -ItemType Directory -Force .tmp | Out-Null
$captureProcess = [System.Diagnostics.Process]::new()
$captureProcess.StartInfo.FileName = (Get-Command adb).Source
$captureProcess.StartInfo.Arguments = 'exec-out screencap -p'
$captureProcess.StartInfo.UseShellExecute = $false
$captureProcess.StartInfo.RedirectStandardOutput = $true
$null = $captureProcess.Start()
$captureFile = [System.IO.File]::Create([System.IO.Path]::GetFullPath('.tmp/tiktok_affiliate_screen.png'))
$captureProcess.StandardOutput.BaseStream.CopyTo($captureFile)
$captureFile.Close()
$captureProcess.WaitForExit()
if ($captureProcess.ExitCode -ne 0) { throw "ADB screenshot failed: $($captureProcess.ExitCode)" }
```

ภาพชั่วคราวให้อยู่ใน `.tmp/` และลบเมื่อจดข้อมูลเสร็จ หลีกเลี่ยงการแตะปุ่ม Buy now หรือ Add to showcase ขณะเก็บข้อมูล

## 3. เกณฑ์อ่านแนวโน้ม

บันทึก **ชื่อสินค้า/SKU, ราคาที่เห็น, Earn ต่อออเดอร์, วันที่ตรวจ, ช่วงวันที่, Orders, CTR, Number of creators, Add-to-cart users, ทิศทางปลายกราฟ** เป็นคนละช่อง ห้ามนำตัวเลข `sold` ทั้งหมดบนหน้าสินค้ามาแทน `Orders` ของช่วง 7 หรือ 30 วัน

- **ยอดล่าสุด:** บันทึกอันดับ Top selling และยอด `sold past week` หรือ `Orders` ใน Last 7 days
- **รูปกราฟ:** บันทึกทิศทางของเส้น Orders ใน Last 7 days และ Last 30 days แยกกัน อย่าสรุปจากยอดรวมของช่วงเดียว ลูกศรบนจอเป็นค่าการเปลี่ยนแปลงที่แอปแสดง แต่หน้าคำอธิบายที่ตรวจไม่ได้ระบุฐานเปรียบเทียบ จึงต้องบันทึกตามที่เห็นโดยไม่เดาว่าเทียบกับช่วงไหน
- **ข้อมูลที่สวนทางกัน:** ถ้าปลายกราฟ Orders ช่วง 7 วันลดลงหรือ Add-to-cart users ลดลง ให้จดตัวเลขและทิศทางนั้นไว้ แม้ตัวเลขช่วง 30 วันจะแสดงลูกศรขึ้น
- **ข้อมูลไม่ครบ:** ถ้ากราฟไม่โหลด ชื่อรุ่นไม่ชัด หรือราคาเป็นเพียง `From ฿…` ให้บันทึกข้อจำกัดไว้โดยไม่ฟันธงแนวโน้ม

### ตัวอย่างที่ตรวจบนมือถือ 2026-10-13

สินค้า **MOJUE [TIS] C704 PD27W Type-C to Lightning** แสดง `Earn ฿4.36 per sale` และราคา `From ฿5.45` (ราคาเริ่มต้น ไม่ยืนยันราคาของทุกตัวเลือก)

| ช่วงที่เลือก | Orders | CTR | Number of creators | Add-to-cart users | ภาพกราฟ Orders |
| --- | ---: | ---: | ---: | ---: | --- |
| 6–12 ต.ค. 2026 (7 วัน, UTC+0) | 8.2K ▲197 | 2.7% 0% | 3.0K ▲207 | 8.8K ▼887 | ขึ้นช่วงกลางแล้วลงที่ปลายกราฟ |
| 13 ก.ย.–12 ต.ค. 2026 (30 วัน, UTC+0) | 32.3K ▲9.1K | 2.6% 0% | 4.1K ▲1.3K | 40.3K ▲9.8K | ไต่ขึ้นตลอดช่วงและแผ่วใกล้ปลายกราฟ |

**บันทึกตามที่เห็น:** Last 30 days แสดง Orders 32.3K พร้อม ▲9.1K และเส้นกราฟไต่ขึ้น ส่วน Last 7 days แสดง Orders 8.2K พร้อม ▲197 แต่ปลายเส้นกราฟลดลง และ Add-to-cart users แสดง ▼887 ข้อมูลบนจอนี้ยังไม่เพียงพอให้ฟันธงสถานะ “ขาขึ้นต่อเนื่อง” ของสินค้า

## 4. เมื่อกราฟไม่ขึ้น

ตรวจว่าหน้าต่าง **Promotion info** เปิดและเลื่อนถึง **Product trends** แล้ว หากหน้า **Analytics** ที่เปิดจาก `sold past week` แจ้ง `Something went wrong` ให้กลับมาดูกราฟใน Promotion info ตามขั้นตอนข้างบน ซึ่งเป็นคนละหน้ากัน ถ้ายังไม่โหลด ให้บันทึกเฉพาะค่าคอมและยอดขายที่อ่านได้ พร้อมระบุว่าไม่มีหลักฐานกราฟสำหรับตัดสินแนวโน้ม
