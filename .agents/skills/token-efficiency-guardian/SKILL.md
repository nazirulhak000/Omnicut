# ⚡ Token Efficiency Guardian (สกิลคุมงบและประหยัดโทเคนสูงสุด)

คู่มือและกฎเหล็กสำหรับ AI Assistant ในโปรเจกต์นี้ เพื่อให้การทำงานมีประสิทธิภาพสูงสุดโดยใช้โทเคนน้อยที่สุดอย่างชาญฉลาด

---

## 🛑 1. กฎการอ่านไฟล์ (Zero Unnecessary File Reads)

1. **ห้ามอ่านไฟล์ทั้งไฟล์โดยไม่ระบุช่วงบรรทัด (Never Read Whole Big Files):**
   - ไฟล์ขนาดใหญ่ เช่น `ContentTrackerHub.jsx`, `ProductToClip.jsx`, `EditorShell.jsx` (2,000–3,600+ บรรทัด) **ห้ามเปิดอ่านทั้งไฟล์เด็ดขาด**
   - ให้ใช้ `grep_search` หาตำแหน่งฟังก์ชันหรือคำสำคัญก่อนเสมอ แล้วใช้ `view_file` ส่องเฉพาะช่วงที่จำเป็น ($\le 50 - 100$ บรรทัด)
2. **ไม่เปิดอ่านซ้ำถ้าไม่จำเป็น:**
   - เมื่อเห็นโครงสร้างหรือตัวแปรแล้ว ให้ลงมือแก้ทันที ไม่เปิดส่องยืนยันซ้ำซ้อนหลายรอบ

---

## 🚫 2. กฎการจัดการสกิลและเครื่องมือ (Minimal Skill Overhead)

1. **ห้ามโหลด/อ่านสกิลภายนอกที่ไม่เกี่ยวข้อง:**
   - ห้ามแตะสกิล BigQuery, GCP Composer, Dataform, dbt หรือคลาวด์อื่นใดที่ไม่ได้เกี่ยวข้องกับโปรเจกต์ CapCut นี้
2. **ไม่รันคำสั่ง Terminal ที่พ่น Output มหาศาล:**
   - คำสั่งที่แสดงผลยาว เช่น `git log`, `pytest` หรือ `npm test` ให้จำกัดผลลัพธ์เฉพาะจุดที่ทดสอบ ไม่รัน full suite ทั้งระบบพร่ำเพรื่อถ้าแก้แค่ฟังก์ชันย่อย

---

## ✍️ 3. รูปแบบการตอบสนอง (Concise & High-Impact Output)

1. **ตอบตรงประเด็น สั้น กระชับ (Caveman-style Precision):**
   - ไม่อารัมภบท ไม่ทวนคำถามซ้ำยาวๆ
   - สรุปสิ่งที่ทำเสร็จแล้วเป็น bullet point สั้นๆ พร้อมตัวเลขผลลัพธ์จริง
   - นำเสนอคำตอบหรือโค้ดที่แก้เสร็จทันที
2. **คุม Thinking Mode ให้กระชับ:**
   - คิดวิเคราะห์เฉพาะประเด็น ไม่คิดวกวนฟุ่มเฟือย

---
