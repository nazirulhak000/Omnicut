## 1. ทำไมต้องมีกฎนี้

งานในโปรเจกต์นี้กินหลายรอบ หลายวัน และบางทีมี AI มากกว่าหนึ่งตัวทำขนานกัน
(เคยเกิดจริง: สอง session แก้ `EditorShell.jsx` พร้อมกันจนแยก commit ไม่ได้)

ถ้าไม่เขียนแผนลงที่เดียวกันก่อนลงมือ จะเกิด 4 อย่างนี้เสมอ:

| อาการ | ผลที่ตามมา |
| :--- | :--- |
| ไม่รู้ว่ารอบก่อนทำถึงไหน | ทำซ้ำ หรือทำทับของที่เสร็จแล้ว |
| งานใหม่โผล่กลางทางแล้วทำเงียบๆ | scope บาน commit ปนกัน ย้อนกลับไม่ได้ |
| ติ๊กเสร็จเพราะ "เขียนโค้ดจบ" | ของพังแต่ในกระดาษบอกว่าเขียว |
| เจอบั๊กแล้วไม่บันทึก | หายไปกับ session ไม่มีใครรู้ว่าเคยเจอ |

**หลักการเดียว: ถ้ามันไม่ได้อยู่ใน `TODO.md` แปลว่ามันไม่ได้เกิดขึ้น**

## 2. ลำดับบังคับของหนึ่งรอบงาน

ห้ามข้ามข้อ ห้ามสลับลำดับ

### 2.1 อ่านก่อน — ทุกรอบ ห้ามข้าม

- [ ] อ่าน `TODO.md` ทั้งไฟล์ ดูว่ารอบก่อนค้างอะไร
- [ ] ดู `git status` ว่ามีงานของใครค้างใน working tree อยู่หรือเปล่า
- [ ] ถ้ามีไฟล์ค้างที่ไม่ใช่ของรอบนี้ → **บันทึกไว้ใน Notes แล้วห้ามเขียนทับ**

### 2.2 เขียนแผนลง TODO.md **ก่อน** แตะโค้ดบรรทัดแรก

เพิ่มบล็อกรอบใหม่ต่อท้ายหัวข้อ `## รอบงาน` ตามฟอร์แมตข้อ 3
แล้วติ๊ก `- [ ] Round N` ลงในหัวข้อ `## สถานะรวม` ด้านบน

> ห้ามเริ่มแก้โค้ดโดยที่ `TODO.md` ยังไม่มีบล็อกของรอบนี้ — แม้เป็นงานแก้บรรทัดเดียว

### 2.3 ลงมือตาม Todo ที่เขียนไว้

- ทำทีละข้อ ตามลำดับที่เขียน
- **เจองานใหม่ระหว่างทาง → ไปข้อ 2.6 ก่อน ห้ามแอบทำ**

### 2.4 รัน Gate จริง

- Gate ต้องเป็น **คำสั่งที่รันได้จริง** ไม่ใช่ "ตรวจแล้วน่าจะโอเค"
- ห้ามสรุปผลจากการอ่านโค้ด
- งานที่มีผลต่อภาพในวิดีโอ ต้องรัน ffmpeg ดึงเฟรมมาดูจริง ตาม
  [preview_render_parity.md](file:///d:/Winona/Programmer/Capcut/.agents/rules/preview_render_parity.md)

### 2.5 ติ๊กและเขียน Notes

- ติ๊ก `[x]` **เฉพาะข้อที่ Gate ผ่านแล้วเท่านั้น**
- Notes ต้องมี **ตัวเลขจริง** (เช่น `294 passed, 0 failed` ไม่ใช่ `เทสผ่าน`)
- Gate ไม่ผ่าน → ปล่อย `[ ]` ไว้ แล้วเขียนใน Notes ว่าติดตรงไหน

### 2.6 งานใหม่ที่โผล่กลางทาง

เมื่อเจอบั๊ก เจอของที่ควรแก้ หรือ user สั่งเพิ่มระหว่างรอบ:

1. เขียนลง `TODO.md` ทันที ใต้ `## งานค้าง (Backlog)`
2. ตัดสินใจอย่างใดอย่างหนึ่ง แล้วบันทึกเหตุผล:
   - **ทำในรอบนี้** → ย้ายขึ้นมาเป็น Todo ของรอบนี้ (แก้ Gate ให้ครอบด้วย)
   - **ไม่ทำในรอบนี้** → คาไว้ใน Backlog พร้อมเหตุผลว่าทำไมถึงยังไม่ทำ
3. ห้ามทำเงียบๆ แล้วค่อยบอกทีหลัง

### 2.7 ปิดรอบ — ต้องย้ายเข้า HISTORY.md

- [ ] เขียน Notes ให้ครบ: ผลเทสจริง / สิ่งที่เปลี่ยนพฤติกรรม / สิ่งที่เจอแต่ไม่ได้แก้
- [ ] **ระบุตัวตนผู้ดำเนินการเสมอ**: ใส่ฟิลด์ `ดำเนินการโดย: <Agent Tooling> (<AI Model>)` (เช่น `ดำเนินการโดย: Antigravity (Gemini 2.5 Pro)` หรือ `Claude Code (Claude 3.7 Sonnet)`) ทั้งในหัวบล็อกรอบและในตารางสารบัญ เพื่อให้รู้ว่าโมเดลตัวไหนรับผิดชอบงานนั้น
- [ ] **ย้ายบล็อกรอบทั้งก้อนจาก `TODO.md` ไปต่อท้าย [HISTORY.md](file:///d:/Winona/Programmer/Capcut/HISTORY.md)**
      พร้อมเพิ่มหนึ่งแถวในตารางสารบัญด้านบนของไฟล์นั้น
- [ ] ใน `TODO.md` ลบบล็อกนั้นออกจาก `## รอบงาน` แล้วเอาชื่อรอบไปต่อในบรรทัด **"ปิดไปแล้ว"** ใต้ `## สถานะรวม`
- [ ] รายงาน user: **ทำอะไรไป · ยังค้างอะไร · เจออะไรที่ยังไม่ได้แก้**

> ทำไมต้องย้าย: `TODO.md` เคยโตถึง 293 บรรทัดภายใน 4 รอบ จนงานที่ยังไม่เสร็จจมอยู่ใต้ประวัติ
> `TODO.md` ตอบว่า "ยังเหลืออะไร" · `HISTORY.md` ตอบว่า "ทำอะไรไปแล้วบ้าง" — คนละคำถาม คนละไฟล์

## 3. ฟอร์แมตหนึ่งรอบใน TODO.md

ใช้โครงเดียวกับ `REFACTOR_PLAN.md` เพราะอ่านแล้วเห็นความคืบหน้าทันที

```markdown
## Round 7 — ชื่องานสั้นๆ ที่รู้เรื่อง

วันที่: 2026-09-05 · สั่งโดย: user · ดำเนินการโดย: Antigravity (Gemini 2.5 Pro) · สถานะ: กำลังทำ | เสร็จ | หยุดค้าง

**เป้าหมาย:** ประโยคเดียว ว่ารอบนี้จบแล้วอะไรจะต่างไปจากเดิม

### Todo

- [ ] ข้อที่ทำได้จริงเป็นรูปธรรม ไม่ใช่ "ปรับปรุงระบบให้ดีขึ้น"
- [ ] แตะไฟล์ไหนบ้าง เขียนชื่อไฟล์ไว้ด้วยถ้ารู้แล้ว

### Gate

- [ ] คำสั่งจริงที่ต้องเขียว เช่น `python -m pytest tests/ -q`
- [ ] `npm run build` ผ่าน
- [ ] (ถ้าแตะภาพ) เรนเดอร์ ffmpeg แล้วดูเฟรมจริง

### Notes

- ผลเทสจริงพร้อมตัวเลข
- พฤติกรรมที่เปลี่ยนไปจากเดิม (ถ้ามี) — ต้องแจ้ง user ห้ามเงียบ
- เจอแต่ไม่ได้แก้ → ย้ายเข้า Backlog แล้วอ้างอิงไว้ตรงนี้
```

## 4. กฎการติ๊ก (สำคัญที่สุด)

กฎพวกนี้มีไว้เพื่อให้ `TODO.md` เชื่อถือได้ ไม่ใช่แค่สวย

- ❌ **ห้ามติ๊กเพราะเขียนโค้ดเสร็จ** — ต้องผ่าน Gate ของข้อนั้นก่อน
- ❌ **ห้ามติ๊กรวบยอดทั้งเฟส** เพราะคิดว่า "รวมๆ แล้วน่าจะเสร็จ"
- ❌ **ห้ามติ๊กย้อนหลังตอนจะปิดรอบ** โดยไม่ได้รันอะไรเลย
- ❌ **ห้ามลบข้อที่ทำไม่สำเร็จทิ้ง** — ปล่อย `[ ]` ไว้แล้วเขียน Notes ว่าติดอะไร
- ✔️ ข้อที่ตัดสินใจไม่ทำแล้ว ให้ขีดฆ่า `- [ ] ~~ข้อความ~~ (ยกเลิก: เหตุผล)`
- ✔️ Notes ต้องเป็นข้อเท็จจริงที่วัดได้ ไม่ใช่ความรู้สึก

## 5. ขนาดของงานกับความละเอียดของแผน

ไม่ใช่ทุกงานต้องเขียนยาว แต่ **ทุกงานต้องมีบล็อกใน TODO.md**

| ขนาดงาน | ต้องเขียนอะไร |
| :--- | :--- |
| แก้ typo / ปรับข้อความ UI | เป้าหมาย 1 บรรทัด + Todo 1 ข้อ + Gate `npm run build` |
| แก้บั๊ก 1 จุด | เป้าหมาย + Todo + Gate ที่มีเทสยืนยันบั๊กนั้นหาย |
| ฟีเจอร์ใหม่ / refactor | ครบทุกหัวข้อ + แตกเป็นเฟสถ้ากินหลายรอบ |
| งานกินหลายวัน | แตกเป็น Phase มี Gate ต่อเฟส เหมือน `REFACTOR_PLAN.md` |

## 6. เมื่อมี AI หรือคนอื่นทำงานขนานกัน

เคยเกิดจริงและทำให้แยก commit ไม่ได้ ต้องกันไว้ก่อน:

- [ ] ก่อนเริ่ม เช็ค `git status` — ถ้ามีไฟล์ค้างที่ไม่ใช่ของเรา **จดชื่อไฟล์ลง Notes**
- [ ] ถ้าไฟล์ที่จะแตะซ้ำกับงานที่ค้างอยู่ → **ถาม user ก่อน** ห้ามแก้ทับ
- [ ] ตอน commit ถ้าในทรีมีงานสองชุดปนกัน ต้องบอก user ตรงๆ ว่าแยกไม่ได้เพราะอะไร
- [ ] ห้าม `git add -A` แล้ว commit โดยไม่ดูรายชื่อไฟล์ที่ staged
