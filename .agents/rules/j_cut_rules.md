# ✂️ กฎและมาตรฐานการตัดต่อแบบ J-Cut (J-Cut Editing Rules for Short-Form Video)

คู่มือและข้อกำหนดทางเทคนิคสำหรับการนำเทคนิค **J-Cut** ไปประยุกต์ใช้ในระบบตัดต่อวิดีโออัตโนมัติ (TikTok, Reels, Shorts) สำหรับ AI Agents และ Video Pipeline

---

## 🎯 1. นิยามทางเทคนิค (Technical Definition)

**J-Cut (Audio Lead-in / เสียงมาก่อนภาพ)** คือเทคนิคการตัดต่อวิดีโอลำดับชั้นสูงที่ **"เสียงของฉากถัดไปเริ่มเล่นก่อนที่ภาพจะตัดเปลี่ยน"**
- บนไทม์ไลน์ (Timeline) แทร็กเสียงของคลิปถัดไปจะยื่นเลยไปทางซ้ายใต้คลิปภาพของฉากเดิม ทำให้เกิดรูปทรงคล้ายตัวอักษร **"J"**
- ตรงข้ามกับ **Straight Cut** (ภาพและเสียงตัดพร้อมกันเป๊ะๆ) ซึ่งมักให้ความรู้สึกแข็งทื่อ กระตุก และดูเหมือนงานตัดต่อทั่วไป
- ตรงข้ามกับ **L-Cut** (ภาพตัดไปฉากใหม่แล้ว แต่เสียงฉากเดิมยังคงดังพูดต่ออีกนิดหน่อย)

```
[ ภาพ (Video) ] : [ === ฉากที่ 1 (Shot A) === ] | [ === ฉากที่ 2 (Shot B) === ]
[ เสียง (Audio) ] : [ === เสียง A === ] | <J-Cut> [ ======= เสียง B ======= ]
                                         └─ เสียง B เริ่มก่อนภาพ B ตัดมา ─┘
```

---

## 🚀 2. ทำไม J-Cut จึงเป็นกฎเหล็กสำหรับคลิปขายของ TikTok & Reels?

1. **สร้างความอยากรู้อยากเห็นล่วงหน้า (Anticipation & Curiosity):**
   - เมื่อคนดูได้ยินประโยคใหม่ หรือได้ยินเสียง SFX / คำว่า *"ดูนี่ด่วน!"* ก่อนที่ภาพจะเปลี่ยนเพียงเสี้ยววินาที สมองจะตื่นตัวและตั้งตารอดูภาพช็อตต่อไปทันที
2. **รักษาความต่อเนื่องและเพิ่ม Retention Rate (Eliminates Jarring Cuts):**
   - การตัดภาพพร้อมเสียงตรงๆ ทุก 1.5 - 2.5 วินาที จะทำให้คลิปดูเร่งรีบแบบกระชาก แต่ J-Cut ช่วยเชื่อมต่อแต่ละมุมกล้อง (B-Roll) ให้เนียนตา ลื่นไหลเหมือนงานสตูดิโอมืออาชีพ
3. **ไร้รอยต่อ Dead Air (Zero Dead Air):**
   - การให้เสียงขึ้นก่อนภาพช่วยลดความเงียบและเร่งจังหวะของวิดีโอแนวสั้น (Short-form Fast Pacing) ให้น่าติดตามตลอด 30-40 วินาที

## ⏱️ 3. มาตรฐานระยะเวลา (J-Cut Timing Specifications)

ระบบตัดต่ออัตโนมัติต้องคุมค่าเวลาของ J-Cut ตามเกณฑ์มาตรฐานนี้:

| องค์ประกอบ | ระยะเวลาที่เสียงเริ่มก่อนภาพ (Lead-in Offset) | จุดประสงค์ |
| :--- | :--- | :--- |
| **Voiceover J-Cut (เสียงพากย์หลัก)** | **`150ms – 250ms`** (ค่ามาตรฐาน `0.18s` / `180ms`) | เสียงพูดของท่อนถัดไปดังขึ้นก่อนภาพฉากใหม่เปลี่ยน เพื่อดึงสายตา |
| **Transition SFX (Whoosh / Swish)** | **`100ms – 180ms`** (ค่ามาตรฐาน `0.15s` / `150ms`) | เสียงเหวี่ยงเริ่มก่อน และจุดพีคของ Whoosh จะตรงกับรอยต่อภาพพอดี |
| **Sound Impact / Ding / Pop** | **`0ms` (Synchronous)** | เสียงเอฟเฟกต์ตกกระทบ ให้ตรงกับเฟรมที่ป้ายหรือข้อความเด้งขึ้นมา |

> ⚠️ **ข้อควรระวังเรื่อง Safe Margins:**
> - **ช็อตแรกสุด (Hook 0.0s):** ห้ามทำ J-Cut ย้อนหลัง (Start Time ต้องไม่น้อยกว่า `0.0s`)
> - **ช็อตที่ความยาวสั้นกว่า 0.8s:** ให้ลด J-Cut Offset เหลือไม่เกิน `100ms` เพื่อไม่ให้ภาพฉากแรกถูกเบียดจนสั้นเกินไป

## 🛠️ 4. แนวทางการทำงานในโค้ด Pipeline (Implementation Logic)

เมื่อทำการสร้าง `actual_clip_list` หรือรันคำสั่งตัดต่อใน `scripts/pipeline.py` และ `scripts/video_editor.py`:

```python
# สูตรการคำนวณ J-Cut สำหรับจุดตัดภาพของแต่ละฉาก
J_CUT_OFFSET = 0.18  # 180 milliseconds

for idx, cue in enumerate(cues):
    cue_audio_start = cue["start"]
    cue_audio_end = cue["end"]
    
    if idx == 0:
        # ฉากแรกเริ่มที่ 0.0s เสมอ
        shot_visual_start = 0.0
    else:
        # ฉากถัดไป ภาพจะตัดตามหลังเสียง cue_audio_start เล็กน้อย (J-Cut)
        # ทำให้คนดูได้ยินเสียงของฉากใหม่ก่อนภาพตัด 180ms
        shot_visual_start = cue_audio_start + J_CUT_OFFSET
```

> 📌 สูตรข้างบนคือหลักการ — โค้ดจริง (`scripts/stages/shot_matching_stage.py`) ใช้ `j_lead` ของ `StyleMotionPolicy` (ค่าเริ่มต้น `0.18` s) ปัดเป็นเฟรมที่กริด 1/30 s และจุดตัดแรกคือ `0.0` เสมอ ดูตัวเลขที่วัดจากเรนเดอร์จริงใน **§6**

## 📋 5. สรุป Checklist สำหรับ AI Assistant

- [ ] ทุกครั้งที่มีการแตกช็อตตัดต่อ B-roll หรือฉากที่ AI Vision เลือกมา ให้ประยุกต์ใช้ J-Cut Offset `150 - 250ms`
- [ ] เมื่อใส่เสียง SFX Whoosh ข้ามฉาก ให้วางตำแหน่งก่อนรอยต่อภาพ 150ms (โค้ดจริง: `pre_roll` 0.12 s จาก cue start ⇒ จุดพีคอยู่ ≈167 ms ก่อนภาพตัด อยู่ในช่วง 100–180 ms — ดู §6)
- [ ] ตรวจสอบว่าภาพและเสียงในช็อตสุดท้าย (CTA / ตะกร้าสินค้า) จบพร้อมกันอย่างเรียบร้อย ไม่ขาดหรือล้น
- [ ] วัด lead จริงจากไฟล์ที่เรนเดอร์ (ภาพเปลี่ยน − เสียงเริ่ม) ต้องเป็นค่าบวกทุกรอยต่อ และอยู่ในช่วง 150–250 ms (voice-valley snap อาจขยับได้ ±2 เฟรม แต่โค้ดคุม lead ไว้ที่ 100–300 ms เสมอ) ค่าลบ = reverse J-cut (ภาพมาก่อนเสียง) ถือว่าผิด
- [ ] จุดตัดทุกจุดอยู่บนกริด 1/30 s และเฟรมสุดท้ายไม่ถูกค้าง (held last frame = 0)

## 📏 6. ค่าที่วัดจากเรนเดอร์จริง (EDITOR-CUT-QUALITY-R2, 2026-10-04)

วัดจากไฟล์ MP4 ที่เรนเดอร์จริง (ฟุตเทจสังเคราะห์ที่ถอดดัชนีเฟรมได้ทุกเฟรม + เสียง tone ที่ต้นทุก cue) รายงาน: `_Docs/Reports/R0_REAL_RENDER_MEASUREMENT_20261004.md` · เทส `tests/test_real_render_cut_alignment.py`

1. **จุดตัดแรก = `0.0` เสมอ** (เดิมใช้ `first_cue_start` ทำให้คลิปรวมสั้นกว่าเสียง `first_cue_start` วินาที จึงค้างเฟรมท้าย และ lead ของทุกรอยต่อลดลงเท่ากัน) — ตอนนี้คลิปรวมยาวเท่าเสียง ไม่มีเฟรมท้ายถูกค้างอีก

   | `first_cue_start` | lead เดิม (ภาพเปลี่ยน − เสียงเริ่ม) | lead ตอนนี้ | เฟรมสุดท้ายที่ถูกค้าง เดิม → ตอนนี้ |
   | :--- | :---: | :---: | :---: |
   | 0.0 s | +200 ms | ≈ +167 ms | 0 → 0 |
   | 0.1 s | +100 ms | ≈ +167 ms | 3 → 0 |
   | 0.3 s | **−100 ms** (reverse J-cut) | ≈ +167 ms | 9 → 0 |

   lead ≈ 167 ms คือค่าเริ่มต้น `j_lead` 0.18 s ที่ปัดเป็น 5 เฟรม และ**ไม่ขึ้นกับ `first_cue_start`** ทุกรอยต่อ
2. **Transition วางกึ่งกลางจุดตัด** — ปลายคลิปขาออกต่อเพิ่ม `d/2` และหัวคลิปขาเข้าต่อเพิ่ม `d/2` (ขยับ `trim_start` ถอยหลัง) จุดกึ่งกลางของ wipe 0.35 s จึงตกที่ ≈ 167–183 ms หลังเสียงเริ่ม (เดิม ≈ 350 ms ซึ่งช้าเกินกรอบ J-cut)
3. **กริด 1/30 s สะสม** — จุดตัดทุกจุดปัดแบบสะสม `boundary_k = round(cumsum_k × 30) / 30` ทั้งพรีวิว (`timelineMath.js`) และ render (`video_editor.py plan_sequence_frames`) เฟรมรวม = `round(total × 30)` (เดิมจุดตัดเรนเดอร์ช้าไป ~1 เฟรม และสายคลิป 12 คลิปเลื่อนสะสมได้ถึง +7 เฟรม)
4. **ค่า `j_lead` และ snap ต่อสไตล์** อยู่ใน `scripts/style_motion_policy.py` (`StyleMotionPolicy`: `min_shot`, `max_shot`, `j_lead`, `beat_snap_tolerance`) — ตารางครบทุกสไตล์ดูที่ `_Docs/GADGET_VIDEO_PRODUCTION_SOP.md` Phase 5 ลำดับความสำคัญของ snap: beat > motion > voice-valley > rhythm · **voice-valley snap** ขยับจุดตัดได้ ±2 เฟรมไปยังช่วง 10 ms ที่เงียบที่สุดของแทร็กเสียงพากย์ โดยคุม lead ให้อยู่ในช่วง 0.10–0.30 s
5. **ข้อจำกัดที่ยังค้าง:** จุดพีคของ whoosh ผูกกับ cue start (`pre_roll` 0.12 s) ไม่ได้ผูกกับขอบคลิปสุดท้ายหลัง snap — ตอนนี้อยู่ ≈ 167 ms ก่อนภาพตัด ซึ่งยังในกฎ 100–180 ms แต่ถ้าจุดตัดถูกขยับไกลกว่านี้ค่าจะเพี้ยน · fcs จริงของ Gemini TTS (~0.1–0.4 s) ยังไม่ได้วัดจากไฟล์เสียงจริง (R0 ใช้ tone สังเคราะห์)
